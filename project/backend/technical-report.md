# LovisMind 后端简明技术报告

日期：2026-11-04。分支：`codex/backend-auth`。最新状态：独立预览已部署，正式站未变；未新开通付费服务。旧参数预览曾复现 1102；最新降档后登录 CPU 样本为 4–8ms，仍不等于完整生产性能验收。详见 [哈希降档记录](hash-cost-update.md)。详见 [预览部署记录](preview-deployment.md)。

## 1. 功能与架构

这是“注册审核后阅读”系统，不涉及付费会员。有效邀请码自动通过，无邀请码进入人工审核；管理员可审核、禁用账号、管理邀请码及签发短期密码重置凭据。邮件通知暂未接入。

| 层次 | 实现 |
| --- | --- |
| 前端 | Next.js 静态导出数据无关的页面框架；`/` 为公开入口，`/library/` 为登录后的书库 |
| 后端 | Cloudflare Pages advanced mode Worker；同源 `/api/*`；页面和附件也经过后端访问检查 |
| 数据库 | D1 保存用户、会话、邀请码、审核记录、重置凭据、限流计数及版本化阅读内容 |
| 内容 | 原 Markdown 目录与归属不变；16 本书、177 章经导入脚本进入 D1，正文由鉴权接口返回 |

## 2. 认证与数据一致性

- 新设置的密码恢复为 6–128 个字符，不限制纯数字。scrypt-v2 使用原生实现及 `N=512,r=8,p=1` 和随机盐，主要内存工作区约 0.5 MiB；保留 scrypt-v1 的原参数兼容验证及成功登录迁移。
- 会话令牌为 256 位随机值，D1 只保存令牌哈希；Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax` 和 `__Host-` 前缀，有效期七天。
- 每个受保护请求检查当前会话与账号状态。退出撤销当前会话；禁用、重置凭据签发及密码变更撤销相关旧会话。
- 普通注册不能指定管理员身份。首位管理员由终端脚本创建；审核备注和管理接口仅管理员可访问。
- 邀请码只在创建时展示明文。数据库触发器把用户创建、有效性检查和次数扣减放在同一事务中，注册失败不消耗次数。
- 修改接口有同源检查和 CSRF 防护；注册、登录、邀请码尝试及密码重置有限流。审核使用版本号防止覆盖并发操作。

## 3. CPU 超限会发生什么

CPU 时间是实际执行计算的时间，等待数据库和网络通常不计入。Workers Free 每次 HTTP 请求限额为 10ms；持续超限会被平台中止，并返回 Cloudflare 1102 资源超限错误，监控中记为 `exceededCpu`。这与每天请求总额度是不同的限制。[Cloudflare 官方说明](https://developers.cloudflare.com/workers/platform/limits/)

结合当前代码，影响如下；现已在预览实测复现 1102：

| 场景 | 可能表现 |
| --- | --- |
| 注册、登录、密码重置 | 密码哈希开销较高，最可能触发超限；用户点击后看到请求失败，严重时每次重试仍失败 |
| 已登录阅读、普通管理查询 | 不重新计算密码哈希，预期开销较低；不等于已证明符合免费额度 |
| 前端错误显示 | 平台可能返回 HTML 错误页而非 API JSON，当前界面可能出现解析错误，上线前应统一为友好的重试提示 |
| 数据库 | 超限不等于清空数据库；若写入已提交而响应未送达，用户可能看到失败但数据已经保存，需按实际状态处理重试 |

平台强制中止不能指望由 Worker 内部普通 `try/catch` 完整接管。邀请码相关单次数据库事务仍保持原子性；整个 HTTP 请求与所有数据库操作并非一个整体事务。

另一个独立风险是每天免费请求额度耗尽。Pages 的 fail-open 设置可能跳过 Functions 继续提供静态资源；生产与预览均应设置为 **fail closed**，避免绕过附件鉴权。该设置不是提高单次 CPU 上限的方法。[Pages 官方说明](https://developers.cloudflare.com/pages/functions/routing/#fail-open--closed)

## 4. 已验证与尚未验证

已通过：28 项本地认证、格式兼容和前端错误响应测试、生产构建、类型检查、1,257 个文本产物的抽样泄露扫描，以及语言和内容刷新检查。浏览器已验证申请、审核、登录阅读、邀请码自动通过与撤销，并检查了桌面阅读及手机登录界面。抽样扫描不是完整的安全审计。

已优化重复用户名注册和非法格式登录的提前返回；普通会话查询只读取必要字段。先前的原生实现对比不足以证明满足额度；当前已按用户要求降低哈希参数并采用原生实现，具体参数、迁移方式与测量结果见降档记录。

本地哈希测量只能用于判断风险，不能直接代表 Cloudflare 生产 CPU 计量。预览日志现已记录注册请求 CPU 540ms、登录请求 CPU 434ms 和 382ms；成功请求之外，后续登录已被平台以 1102 中止。**目前不能承诺额度足够，也不能把本地正常使用等同于云端上线验收。** 并发密码哈希还需验证内存余量。

## 5. 正式上线前的必要步骤

1. 按用户后续授权选择运行计划；不自动开通付费。建立独立预览、生产 D1，替换配置中的占位 UUID，确认 Pages 构建根目录与绑定。
2. 在预览环境测正常登录、错误密码、注册、重置和并发访问的 CPU、内存、错误率及延迟；依据实际数据判断免费方案是否可行。
3. 完善平台非 JSON 错误响应提示，配置 fail closed，复测静态直链、附件、退出、禁用和重置后的访问。
4. 单独初始化生产管理员，配置日志和监控，并确认旧公开部署的处理及回滚步骤，再发布生产。

边界：用户已选择保留公开 GitHub 源码，因此网站登录限制不能让仓库中的原文保密，也不能收回历史已公开内容。当前交付已进入独立预览验证阶段，尚不是已完成云端性能验收的生产版本。

具体命令与接口见 [部署及维护说明](README.md)。
