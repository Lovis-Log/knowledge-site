# 密码规则恢复与哈希计算降档

> 历史变更与测量记录，不代表当前容量承诺。现行账号规则见 [README](README.md)，发布与恢复见 [RELEASING.md](../RELEASING.md)。

2026-11-04；已更新独立预览分支，正式站未改动。

## 本次变更

- 新设置的密码恢复为 6–128 个字符，不再限制纯数字；注册、重置、首管初始化统一执行。原密码不自动改变。
- 新哈希采用平台原生 `node:crypto.scryptSync`，参数为 `N=512,r=8,p=1`，随机盐 16 字节、输出 32 字节，编码为 `scrypt-v2$盐$校验值`。
- 旧 `scrypt-v1` 保留原参数 `N=32768,r=8,p=3` 的验证能力，不能直接修改旧版本参数。正确密码且账号已通过审核时，登录会以同一密码生成 v2 哈希。
- 迁移通过比较原哈希的条件更新防止覆盖并发重置或禁用；会撤销旧会话。并发迁移已经测试，成功登录的新会话不会因另一迁移请求丢失。
- 随机盐、密码哈希、限流、CSRF、审核与安全 Cookie 保留，没有改为明文保存。本次只调整哈希计算，不引入新的外部服务。

该参数是按用户要求降低计算成本的选择，低于通用密码存储推荐，不称为安全最低线。新哈希的主要工作量约为原参数的 1/192，核心内存工作区约由 32 MiB 降至 0.5 MiB。

## 测量结果

| 指标 | 旧实现 | 新实现 |
| --- | --- | --- |
| 预览注册 CPU | 540ms 样本 | 5ms、4ms |
| 预览登录 CPU | 434ms、382ms 样本 | 8ms、6ms、4ms、4ms |
| 本地单次哈希/验证 | 此前为数十至数百毫秒 | 约 0.7–0.8ms |

上述 CPU 来自预览日志；网络响应时间仍包含 D1 等待，不能与 CPU 混同。这轮注册、邀请码自动通过、连续登录、读取目录与正文、普通用户禁止管理员接口、禁用撤销会话及退出均成功，没有出现 1102。临时 QA 账号、会话和邀请码已清理。

目录接口另有一次 12ms CPU 样本，不能据这轮测试承诺所有请求都不再超限，也不作并发容量保证。28 项本地测试、构建和产物扫描通过。

## 现有账号迁移

新注册和新重置的密码立即使用 v2。旧账号在首次正确登录后自动迁移；首次验证仍需要计算旧哈希，因此可能比之后慢，仍可能受平台资源限制影响。

如旧账号首次登录持续失败，可在本机计算旧哈希验证并迁移，避免把这一笔旧计算放在 Worker 上。在 `project/` 终端执行：

```powershell
node node_modules/tsx/dist/cli.mjs scripts/migrate-password.ts --remote --env=preview
```

按提示输入用户名和当前密码，密码以星号显示，不需要发到聊天。该工具保持原密码、角色和审核状态不变，只更新哈希版本并撤销旧会话。省略 `--remote --env=preview` 时默认操作本地数据库。

迁移后不能直接回滚到仅支持 v1 的旧 Worker；回滚代码仍必须保留 v2 验证能力。正式站尚未采用这套变更。
