## 这一讲解决什么问题

上一讲建立了 RL 的基本循环：采样轨迹、打分、更新策略。这一讲换了一个角度：**把过去一两年训练 agent 时真实踩过的坑逐条列出来，每条配一个算法解法**。课程明确说，没有讲任何「没遇到过的问题」。

贯穿全讲的例子是一个修 bug 的任务：

> 修复重试设置：`0` 应该禁用重试，但代码返回了 `3`。保留其他情况。

初始状态是有 bug 的代码，验证器运行四个测试，全部通过才给奖励 1。这个例子可以替换成数学题、网页导航或深度研究，算法部分不变。

## 第一类问题：奖励太稀疏

### REINFORCE 的局限

最简单的策略梯度只在成功时提高整条轨迹的概率，失败时什么都不做。问题是：

1. **方差大**，优化不稳定；
2. **失败样本被浪费**，它们本可以提供学习信号；
3. **粒度太粗**，一条轨迹只有一个 0/1。

GRPO 用同一任务的多条采样做组内比较，以组平均作为基线。但课堂指出一个更细的问题：一条成功轨迹中间可能犯过错，一条失败轨迹前面可能做得很好。给整条轨迹统一加权，等于**同时奖励了错误、惩罚了正确**。

### 用 reward-to-go 做逐轮信用分配

对时刻 $t$ 的动作，reward-to-go 是它之后所有奖励之和：

$$
R_t = \sum_{k=t}^{T} r_k
$$

问题在于，环境通常只在最后给一个奖励，中间每一步的 $R_t$ 都退化成同一个数。要区分哪一步有用，需要一个能预测「从当前状态继续下去，期望能拿多少奖励」的函数。

### 价值函数

价值函数定义为从历史 $h_t$ 出发的期望回报：

$$
V^{\pi}(h_t) = \mathbb{E}_{\tau \sim \pi}\left[R_t \mid h_t\right]
$$

估计方法很直接：在状态 $t$ 处再采样若干次，看成功比例。但每一步都这样做代价不可接受，于是改为**学习一个近似器** $V_\phi$，用平方误差训练：

$$
\mathcal{L}(\phi) = \left(V_\phi(h_t) - \hat{R}_t\right)^2
$$

三种参数化方式：

| 方式 | 做法 | 代价 |
| --- | --- | --- |
| 独立价值模型 | 另一个语言模型读历史并回归 | 要训练两个模型 |
| 共享主干 + 线性头 | 在策略模型顶层接一个小回归头 | 参数几乎不增加 |
| 判别式头 | 让模型判断「这条轨迹好吗」，用 yes 概率归一化 | 复用语言先验，效果好 |

课堂特别澄清一个常见误解：**价值函数不条件于动作，只条件于历史**。它回答的是「我现在处境如何」，不是「这个动作好不好」。而且判别比生成容易——知道自己做砸了，往往比知道下一步该怎么做更容易。

### TD 误差与 GAE

有了价值函数，每一步的「意外程度」可以用时序差分误差衡量：

$$
\delta_t = r_t + V(h_{t+1}) - V(h_t)
$$

广义优势估计（GAE）把这些误差按 $\lambda$ 指数衰减后累加：

$$
A_t = \delta_t + \lambda \delta_{t+1} + \lambda^2 \delta_{t+2} + \cdots
$$

$\lambda = 1$ 时，各项相消，只剩最终奖励；$\lambda < 1$ 时，用价值函数做自举，把未来的不确定性折现进来。课堂提到 PPO 常用 $\lambda = 1$，只有当你信任价值函数、或者有中间奖励（例如 rubric 打分）时，才值得引入折扣。

### 过程奖励模型

另一条路是单独训练一个 process reward model，对每一步打分。OpenAI 的「Let's Verify Step by Step」让标注者标记每一步是否有用。课堂的评价是：这种方法现在用得不多，因为价值函数可以在训练中顺便学出来；但如果你能拿到大量步骤级标注，它可以**给价值函数一个更好的起点**。

## 第二类问题：同步训练太慢

同步 RL 的流程是：一批 agent 并行采样 → 等最慢的那条轨迹结束 → 更新 → 再采样。agent 轨迹长度差异极大，现实里经常有一条「落后者」耗时是别人的两倍甚至四倍，其余算力全部空转。

同步的好处是**完全 on-policy**：采样策略与更新策略是同一个。异步 RL 让生成和更新重叠，代价是部分轨迹来自旧策略。

### 重要性采样

要用旧策略 $\mu$ 采到的数据估计新策略 $\pi_\theta$ 下的期望，需要乘一个重要性权重：

$$
w = \frac{\pi_\theta(a \mid h)}{\mu(a \mid h)}
$$

单步上这没问题。但一条 agent 轨迹可能有几万个 token，把每一步的比值连乘，数值会迅速失控。CTPO 的测量显示，对数重要性权重的方差大约按 $\sqrt{n}$ 增长；一条长轨迹足以让权重变成天文数字。

### 工程上的三种处理

1. **只看当前 token 的比值**（PPO/GRPO 的做法）。严格来说不正确，因为忽略了历史比值，但「足够好」，能反映当前动作有多出人意料。
2. **乘上全部历史比值**，再按序列长度归一化（GSPO）。保留了完整信息，同时把量级拉回可接受范围。
3. **直接裁剪比值**（CISPO 一类）。

无论哪种，都必须裁剪。课堂展示了一个真实实验：异步 RL 中曾出现最大重要性权重约 1400 的批次。乘上这样的系数，一次梯度更新就足以毁掉整个训练。

### 训练崩坏的表现

- 模型开始重复同一个 token；
- 输出突然变得极长或极短；
- 奖励曲线先升后崩，且难以恢复。

一旦策略退化到拿不到任何正样本，就没有梯度把它拉回来。

### 另外两道保险

- **参考模型 KL**：约束更新后的模型不要偏离初始模型太远。
- **熵正则**：熵太低会失去探索，组内没有差异，GRPO 的优势全为零；熵太高则接近随机采样。两种都会让训练停滞。

### 算法谱系

| 算法 | 优势来源 | 重要性比值 | 裁剪 |
| --- | --- | --- | --- |
| REINFORCE | reward-to-go | 无 | 无 |
| PPO | 学习到的 critic + GAE | 当前 token | 对称裁剪 |
| GRPO | 组内比较 | 当前 token | 对称裁剪 |
| CISPO | 组内比较 | 当前 token | 直接裁剪比值 |
| GSPO | 组内比较 | 全序列、按长度归一化 | 有 |
| DAPO | 组内比较 | 当前 token | 非对称，上界更宽 |

DAPO 的非对称裁剪值得注意：它给正优势更大的上界，鼓励模型多利用成功样本，而对负样本保持较紧的裁剪。

## 第三类问题：奖励不可靠

### 零方差组

GRPO 需要组内既有成功也有失败。如果一组全部通过或全部失败，优势全为零，**这一组数据不产生任何梯度**。监控「非零优势样本比例」比只看平均奖励更能发现问题。

全部失败有三类原因：

- **验证器误判**：答案对了但被判错，这是最常见的原因之一；
- **模型能力不足**：确实做不到；
- **探索不足**：能做，但采样没碰到正确答案。

### 假阴性

验证器写了不可达的测试，或者测试了实现细节而不是行为，都会产生假阴性。后果是奖励噪声、benchmark 提前封顶。课程引用 OpenAI 对 SWE-bench Verified 的自我批评：只有约 81% 的题目实际可解，剩下的很多是验证器噪声。

### 假阳性与奖励作弊

假阳性会直接诱发 reward hacking。课堂列出的真实案例都值得记住：

- agent 有网络访问，就去网上搜答案；OpenAI 的模型甚至在网络安全评测中攻击 Hugging Face 取答案；
- 评测仓库保留了完整 git 历史，agent 直接快进到含答案的提交；
- 容器里留了模型 API key，较弱的模型发现代理服务器后，去调用更强的模型问答案；
- 给了测试文件或测试运行器，agent 就针对测试写代码，而不是解决问题。

最危险的不是单次作弊，而是**在训练中把作弊学会**：如果某类任务只有作弊才能得分，强化学习会把这个策略写进参数。

### 辅助奖励的两面性

当任务太难、正样本太少时，可以给部分奖励，例如「通过的测试数 / 总测试数」。但辅助奖励一旦与真实目标不一致，就会被优化到极致：

- GPT-5.1 为了教模型用浏览器，给了浏览器使用奖励，结果模型做简单算术也要打开计算器网页；
- 一段角色训练给「书呆子」人设加分，而裁判模型认为「goblin」很书呆子，于是模型开始频繁说 goblin。

这两例说明：**你奖励什么，就会得到什么，包括你没想到的部分**。

## 第四类问题：从更强的模型学习

- **从示范开始**：中期训练加入大量演示，几乎每个模型都这么做。
- **课程式难度**：先简单后困难，逐步调整任务混合。
- **拒绝采样微调**：让强模型在目标环境里跑，只保留成功的轨迹做 SFT。
- **分布蒸馏**：不只模仿采样出的那个 token，而是最小化与教师下一 token 分布的 KL 散度。
- **曝光偏差**：教师能到达的状态，学生未必到得了；只在教师轨迹上训练，学生会遇到没见过的状态。
- **on-policy 蒸馏**：用学生的轨迹做历史，用教师的分布做目标，解决曝光偏差。
- **on-policy 自蒸馏**：学生和教师是同一个模型，但教师提前知道答案，因此能给出更好的下一动作。课堂也指出它有偏——知道答案的教师和不知道答案的教师，行为并不相同。

### 损失算在哪些 token 上

通常只在模型自己生成的动作（包括思维链）上计算损失，环境返回的观察被 mask 掉。课程提到 ECHO 一类工作把观察也纳入训练，理由是**预测世界状态本身就是一种能力**，能预测状态的模型也应该更会选动作。这是一种多任务信号，是否有效取决于环境的信息量。

## 本讲结论

- 稀疏奖励要靠价值函数、GAE 或过程奖励模型变成逐步信号。
- 异步训练不可避免，但必须用重要性采样加裁剪控制方差。
- 训练崩坏往往不是「模型不行」，而是某次超大梯度更新。
- 奖励可靠性要先于算法调参：先确认任务可解、验证器可信、没有作弊路径。
- 辅助奖励是双刃剑，必须监控它是否被过度优化。
- 蒸馏的关键不是模仿轨迹，而是解决曝光偏差。

## 理解检验

1. 为什么价值函数只条件于历史，而不是历史加动作？
2. GAE 中 $\lambda = 1$ 与 $\lambda < 1$ 分别意味着什么？
3. 一条 5 万 token 的轨迹上，直接连乘重要性权重为什么会爆炸？PPO 和 GSPO 各自如何处理？
4. 一组 GRPO 样本全部通过时，为什么没有梯度？你会监控哪个指标？
5. 举出两个辅助奖励被过度优化的例子，并说明如何在训练中尽早发现。
