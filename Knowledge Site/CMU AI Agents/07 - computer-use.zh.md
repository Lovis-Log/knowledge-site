## 这一讲的主题

前面几讲的 agent 主要和文本、代码打交道。计算机使用 agent（computer use agent，CUA）换了一个动作空间：**它看到的是屏幕截图，做的是点击、滚动、输入、拖拽这些人类在同一套图形界面里做的动作**。

这意味着它不需要目标软件提供 API，也不需要理解网页的 DOM。只要能截图、能控制鼠标键盘，它就能操作几乎任何程序——网页、桌面应用、手机。代价是动作空间变成像素级的坐标，环境噪声大，评估也更困难。

### 一个最小循环

1. 给定自然语言任务，例如「买一盒 $20 以内的蓝莓」；
2. 环境返回当前截图；
3. 视觉语言模型输出一段推理，再输出一个结构化动作，例如「左键点击坐标 (x, y)」；
4. 基础设施执行动作；
5. 环境返回新截图；
6. 把动作与新截图追加到历史，重复，直到模型认为完成或预算耗尽。

奖励通常是 0/1 的二元信号：任务完成或没有完成。长程任务里也会用部分奖励。

## 发展史：从玩具环境到真实桌面

| 时间 | 工作 | 关键变化 |
| --- | --- | --- |
| 2017 | World of Bits（OpenAI） | 第一个 CUA 论文，合成的小型网页环境，用早期 RL 训练，远超前于当时的模型能力 |
| 2022 | WebShop | 仍然模拟，但更接近真实购物网站，语言模型开始参与 |
| 2024 | WebArena（CMU） | 高保真模拟网站，填充真实数据，约 800 个任务、4 个应用 |
| 2024 | OSWorld | 真实 Linux 虚拟机，369 个任务、9 个应用，从网页扩展到完整桌面 |
| 2025–2026 | MyPCBench 等 | 用编码 agent **端到端生成**整个应用与合成数据；环境更干净、可控 |
| 2026 | KA World（CMU） | 转向长尾专业软件，如天文、生物、工程工具 |

课堂上展示的 GPT-6 Astra 演示在 CAD 软件里做三维建模，视频被加速了 30 倍——这说明能力已经很强，但**仍然慢且贵**。

一个值得记住的判断：环境本身正在被模型生成。早期基准需要人类先写好开源应用再灌数据；现在可以让编码 agent 直接生成一个 Gmail 克隆并填入合成数据，质量甚至比真实网站更干净。

## 四类评估方式

计算机使用任务的「成功」不像数学或软件工程那样容易用单元测试判定，因此评估被拆成几种互补的做法。

### 1. 静态评估：看每一步动作

给定一张截图和一个任务，判断模型预测的下一步动作是否落在标准答案的包围盒内。

- **ScreenSpot-Pro**：约 1,500 个截图样本，覆盖多种应用与操作系统，测的是「 grounding 」能力——能不能把「这个按钮」落到正确的像素区域。
- **Mind2Web**：下一动作模仿，给当前截图与任务，预测人类会点击哪里。

优点是非常快、非常便宜，不需要真实环境。缺点是**假阴性多**：同一个任务往往有多种正确走法，标准答案只收录了其中一种，其他合理动作会被判错。它测量的是「像不像标注者」，而不是「有没有完成任务」。

### 2. 端到端评估：看最终状态

在可控环境里让 agent 完整执行任务，最后用程序化检查验证状态。

- **WebArena**：约 800 个任务、4 个模拟应用，验证器由 CMU 的研究生手写；只检查结果，不监督每一步。
- **VisualWebArena**：910 个必须依赖视觉信息才能完成的任务，推动社区从无障碍树转向截图。
- **OSWorld**：真实 Linux 虚拟机，369 个任务、9 个应用，例如根据收据更新 LibreOffice 表格并保存。
- **Windows Agent Arena**：微软面向 Windows 企业工作流的同类基准。

这种评估更接近真实目标，但有两个风险：验证器不全面会带来假阳性/假阴性；agent 可能**奖励作弊**——不去完成任务，而是去满足验证器的检查条件。

### 3. LLM 评委：看轨迹

当无法为每个任务写验证器时，把任务和完整轨迹交给另一个 VLM，让它判断成功与否。

- **WebVoyager**：15 个真实网站、600 个任务，直接在真实互联网上操作。
- **Online-Mind2Web**：扩展到 136 个真实网站、300 个任务，评委与人类的一致率约 85%。

真实网页评估最接近现实，但没有程序化验证器，评委可能被表面证据骗过；而且大量 agent 访问会给网站带来真实流量，站点所有者并不欢迎。课堂的判断是：这类基准现在用得少了，一是已被现代模型基本解决，二是部署真实 agent 的顾虑变多。

### 4. 长程评估：看过程与部分得分

长程任务的最终奖励非常稀疏——agent 可能做了大量有用工作，却在最后一步失败，最终得 0。因此这类基准改用**多条评分细则（rubric）**给出中间分。

- **Odyssey**（CMU）：200 个长程网页任务，每个任务有 8 条左右的细则，例如「找到匹兹堡到洛杉矶的直飞航班」「把驾车时间安排在 9:00–16:00」。
- **OSWorld 2**：108 个任务，中位数需要人类 1.6 小时，前沿 agent 平均约 300 次调用；包含 CAD 建模、照片编辑等专业工作流。
- **KA World Long**：200 个专业领域任务，多数需要 500 次以上调用。

评分细则常见做法是 LLM 生成、人类校验；生成时可以给模型「特权信息」（例如网页 HTML），让它先做对，再据此写细则。

## 模型是怎么建的

### 表示：交错的视觉—语言历史

CUA 本质上仍是一个视觉语言模型。输入是自然语言目标加上截图序列，输出是文本形式的结构化动作。历史不断累积：

```text
[目标] [截图0] [动作0] [截图1] [动作1] [截图2] ...
```

文本被 tokenize 成文本 token，截图被编码成视觉 token，两者直接拼接后送入 Transformer。模型在每一步基于整段历史预测下一个动作。

坐标通常被**归一化到 0–1000**，与绝对分辨率无关，因此在 Mac 上训练的策略可以迁移到平板或不同分辨率的屏幕。

### 动作空间

不同模型的动作集合略有差异，但大体相似：点击、滚动、输入、拖拽、按键。表示方式可能是 pyautogui 调用、工具调用 JSON，或 XML 标签；环境侧需要解析成真正可执行的指令。

### 为什么主要用截图而不是 HTML

HTML 很脏，桌面应用也拿不到统一的 DOM；截图则对所有设备一致。课堂上提到，截图方案的性能好得超出预期，以至于结构化表示显得不那么必要。

不过，前沿模型在可获得时会同时使用**无障碍树**等元数据，因为这类结构信息能提升鲁棒性。纯截图的好处是通用：训练在 Windows 上的模型更容易迁移到 Linux 或 macOS。

### 工程细节：加载与等待

执行动作后通常先睡眠约 3 秒再截图；如果截到加载页，模型会被训练为再等一段时间。更复杂的系统会等到画面变化再继续，但「睡一会儿」是最常见的做法。

## 三段式训练

### 1. 预训练：定位与 grounding

目标是让模型学会「屏幕上的东西在哪」。数据形式是截图加包围盒加坐标，模型学习输出元素的位置。这类数据可以大规模自动生成——在网页上跑一段 JavaScript 就能导出所有元素的包围盒。

同时会加入动作预测数据：给截图和任务，预测下一步动作。数据噪声大，但量可以很大。这一阶段只建立最基础的能力：看懂截图、定位元素、理解元素之间的相对关系。

### 2. 后训练 SFT：模仿人类与合成轨迹

- **人类演示**：Momo Web 收集了约 36,000 条人类操作轨迹；AgentNet 也采用类似方式。每条轨迹是「截图—动作」序列。
- **合成轨迹**：让一个能访问无障碍树的模型（拥有推理时不存在的特权信息）先完成任务，收集轨迹，再丢弃特权信息，只保留截图与动作。Momo Web 用这种方式生成了约 105,000 条合成轨迹，并按质量筛选。

课堂上用特斯拉做类比：训练时车上装着激光雷达，收集轨迹后丢掉雷达数据，只让模型学像素输入。**教师看到的信息比学生多，学生因此学得更好**。

### 3. 强化学习：在模拟环境里试错

把模型放进模拟环境，让它自主行动，根据结果给奖励，再更新策略。成功的轨迹被提高权重，失败的被降低。这个过程不需要人类演示。

为什么必须用模拟环境：真实世界里反复订车、下单、退款很快会被封号或烧钱。模拟环境让试错成本可控。

课堂给出的数字：SFT 之后成功率大约 0.5，加上 RL 后可以到 0.6 以上。更重要的是，长程能力很难靠人类演示获得——收集几小时长的人类轨迹极其昂贵，而 RL 可以在模拟环境里反复练习。

## 仍然开放的问题

- **速度**：能力已接近或超过人类中位数，但推理仍然慢且贵。
- **个性化**：如何适配单个用户的习惯与偏好。
- **基础设施与体验**：加载、弹窗、权限、分辨率适配等工程问题占很大比重。
- **多智能体**：多个 CUA 协作完成跨应用任务。

## 本讲结论

- CUA 的价值在于**与人共用同一套界面**，因此不依赖 API，也不受应用是否开放的限制。
- 评估没有单一答案：静态评估快但假阴性多，端到端验证器接近真实但可能被奖励作弊，LLM 评委灵活但不稳，长程任务需要细则化评分。
- 模型训练分三段：预训练学定位，SFT 学模仿（人类加合成），RL 学在环境中最大化奖励。
- 截图是通用表示，无障碍树是有效补充；坐标归一化带来跨分辨率迁移。

## 理解检验

1. 静态评估和端到端评估分别在测量什么？各自的假阳性/假阴性来自哪里？
2. 为什么长程任务更适合用评分细则而不是单一成功/失败？
3. 合成轨迹里的「特权信息」指什么？为什么丢弃它之后学生模型仍然能学到东西？
4. 为什么 CUA 的强化学习几乎必须在模拟环境中进行？
5. 纯截图表示相比 HTML/无障碍树，优势与代价分别是什么？
