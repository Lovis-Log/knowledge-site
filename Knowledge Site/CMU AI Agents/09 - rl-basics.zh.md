## 一个用来贯穿全讲的玩具任务

**Number Search**：环境里藏着一个 1 到 16 的整数，agent 最多猜四次。每次猜完，环境回答「高了」「低了」或「正确」。猜中得 1 分，四次都没中得 0 分。

最优首猜是 8，因为一次就能把候选集砍半——和 Wordle 的首猜思路相同。首猜 4 也能靠反馈最终猜中；首猜 16 或从 1 开始逐个递增，则很可能在四次内失败。

这个任务足够简单，可以手算轨迹概率；又包含多步决策、稀疏奖励和部分可观测，几乎所有 RL 概念都能在这里演示。

## SFT 的三个结构性缺陷

监督微调最大化的目标是：在给定真实历史时，让模型给被演示动作的概率尽量高。

$$
J_{\text{SFT}}(\theta) = \sum_{t} \log \pi_\theta(a_t^* \mid h_t)
$$

但这和「让任务成功」不是同一个目标。

### 1. 任务错位

- 完成任务往往有多条路径：首猜 8 最好，首猜 4 也可行。演示只记录了其中一条。
- 更严重的是：**没被演示的动作一律被当成同样差**。反馈是「高了」，模型猜 7 和猜 15 都错，但前者接近正确、后者错得离谱；SFT 的损失看不出这个区别。

### 2. 数据错位

失败的轨迹也包含信息——它告诉模型「不要这样做」。但 SFT 只会提高这些动作的概率，所以不能直接拿来训练。

### 3. 暴露偏差

训练时历史来自真实演示；推理时历史来自模型自己。一旦模型走出训练分布，它就没见过这种状态，行为可能完全失准。更糟的是，它没有机会学会**从错误中恢复**。

RL 同时处理这三点：直接优化任务回报、能从失败轨迹中学习、训练数据由当前策略自己生成（on-policy）。

## 把交互写成轨迹

- 策略 $\pi_\theta$：由语言模型参数化的动作分布；
- 任务实例：例如隐藏的数字，agent 看不到；
- 观测：环境返回的信息（「高了」）；
- 动作：下一次猜测；
- 奖励：成功为 1，超时为 0。

轨迹 $\tau$ 是动作与观测交错组成的序列，$h_t$ 是到 $t$ 时刻为止的历史。

轨迹概率可以分解为环境项与策略项的乘积：

$$
p_\theta(\tau) = \prod_t p_{\text{env}}(o_t, r_t \mid h_t, a_t)\, \pi_\theta(a_t \mid h_t)
$$

关键点是：**我们不需要知道环境项**。与环境交互就是在从它采样。这也解释了 RL 为什么昂贵——它只能靠不断试错获得关于梯度的间接信息。

> 课堂补充：这里用的是部分可观测马尔可夫决策过程（POMDP）的写法，因为 agent 看不到真实状态，只能用历史作为条件。

## 目标：最大化期望回报

$$
J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}\left[R(\tau)\right]
$$

课堂用一个只有四条可能轨迹的简化例子说明：概率分别为 0.3、0.2、0.25、0.25，其中两条成功。期望回报是 0.5，训练的目标就是把概率质量从失败轨迹移到成功轨迹上。

## 最简单的做法：专家迭代与 REST

在进入策略梯度之前，有一个几乎不需要新数学的基线：**Reinforced Self-Training（REST）**。

1. 用当前策略采样一批轨迹；
2. 计算奖励；
3. 只保留成功的轨迹（二值奖励时就是阈值过滤）；
4. 在这些轨迹上做普通 SFT；
5. 重复，把新采样的成功轨迹不断加入训练集。

它复用了 SFT 的全部基础设施，本质是「自训练 + 奖励过滤」。它不是严格意义上的 RL，但已经具备 RL 的核心结构：数据由模型自己生成，更新方向由奖励决定。

一个现实问题：如果模型一条成功轨迹都采不到，REST 和 RL 都无从下手。解决办法包括——先用少量演示做冷启动、选择当前能解出的课程任务、加入中间奖励，或者用奖励塑形引导模型先完成有价值的子步骤。

## 策略梯度：REINFORCE

直接对 $J(\theta)$ 求导有两个障碍：

1. 动作是从分布中**采样**出来的，采样操作不可导；
2. 环境是黑盒，几乎不可导。

经典解法是 1992 年的 REINFORCE。对期望求导并做「得分函数」变换：

$$
\nabla_\theta J(\theta)
= \sum_\tau \nabla_\theta p_\theta(\tau)\, R(\tau)
= \mathbb{E}_{\tau \sim \pi_\theta}\left[R(\tau)\, \nabla_\theta \log p_\theta(\tau)\right]
$$

而轨迹的对数概率梯度可以拆成每一步动作的梯度之和，环境项与参数无关，直接消失：

$$
\nabla_\theta \log p_\theta(\tau)
= \sum_t \nabla_\theta \log \pi_\theta(a_t \mid h_t)
$$

### 落到实现上

1. 采样一条轨迹；
2. 只对**模型生成的 token** 计算对数概率（工具结果、提示词等不计）；
3. 把整条轨迹的所有 token 对数概率乘以同一个标量奖励；
4. 反向传播。

课堂的观察很直接：这看起来几乎就是 SFT 的梯度计算，只是在前面乘了一个奖励。一个动作可能对应多个 token，对数概率相加即可。

## 为什么基础 REINFORCE 不够

看两条轨迹：一条成功，一条失败。

- 成功轨迹的所有动作被奖励 1 上调；
- 失败轨迹的奖励是 0，**乘以 0 后完全不产生更新**。

但我们恰恰想从失败里学。更好的做法是让更新**相对于预期表现**：

- 一个模型本来有 95% 概率做对的简单题，如果偶尔犯一次低级错误，应该被重重惩罚；
- 一道本来就很难的题，失败并不说明动作有多坏。

这就是**优势函数**：

$$
A(h_t, a_t) = Q^\pi(h_t, a_t) - V^\pi(h_t)
$$

它衡量「这个动作比策略的平均表现好多少」。

### 一个具体的优势例子

猜过 8（反馈「高了」）、12（反馈「低了」）之后，答案只能是 9、10、11。

- 猜 11：如果错了，只剩一次机会、两个候选，优势低；
- 猜 10：无论对错都能继续缩小范围，优势高。

## 基线：不改变期望，只降低方差

把奖励减去一个只依赖历史的基线 $b(h_t)$：

$$
\nabla_\theta J = \mathbb{E}\left[(R(\tau) - b(h_t))\, \nabla_\theta \log \pi_\theta(a_t \mid h_t)\right]
$$

因为 $\mathbb{E}[\nabla_\theta \log \pi_\theta(a \mid h)] = 0$，减去基线**不会引入偏差**，只改变估计的方差。

### 两动作的例子

设策略只有一个参数 $\theta$，用 sigmoid 得到选择动作 A 的概率。当前 $\theta$ 使 $p(A)=0.25$，A 的奖励为 1；B 的奖励为 0。

真实梯度是 $p(1-p)=0.1875$。

- 不用基线：采到 A 时估计为 $1 \times 0.75 = 0.75$，采到 B 时为 $0 \times (-0.25)=0$。估计在 0.75 与 0 之间剧烈跳动。
- 用基线 0.5：采到 A 时为 $(1-0.5)\times 0.75=0.375$，采到 B 时为 $(0-0.5)\times(-0.25)=0.125$。期望仍是 0.1875，但两个样本都更靠近真值。

基线可以是常数、奖励的滑动平均，也可以是一个单独训练的模型（actor-critic、PPO）。GRPO 的创新是**不训练额外模型**，直接用同一道题的多条 rollout 估计基线。

> 如果奖励分布在中间步骤而不是只在结尾，把奖励换成「奖励到未来」（reward-to-go），也能进一步降方差。

## GRPO：用组内均值当基线

Group Relative Policy Optimization 的做法：

1. 对同一个任务实例采样一组轨迹（通常约 8 条）；
2. 计算每条轨迹的奖励；
3. 用组内均值作为基线，得到优势：

$$
A_i = R_i - \frac{1}{G}\sum_{j=1}^{G} R_j
$$

4. 用这个优势缩放每条轨迹的 token 对数概率，再做策略梯度更新。

因为基线只依赖提示词与模型本身，这个估计仍然无偏。组内比较只在同一道题内部进行，不同题的难度不会被混在一起。

### DR-GRPO 的两处修正

- **不除以组内标准差**：除以标准差会把不同难度的题「标准化」，优势因此失去对难度的感知。只减均值即可。
- **不除以生成长度**：按生成 token 数归一化会偏袒长而错误的答案。改为除以一个常数（最大可能生成长度）。

原始 GRPO 还包含重要性比率的裁剪与对初始策略的 KL 正则，用来稳定训练；这些留到下一讲。

### 全对或全错，就没有信号

如果一组轨迹全失败，说明题目对当前策略太难；如果全成功，说明太简单。两种情况组内方差为零，优势全为零，学不到东西。应对方式包括：换任务、给提示、加演示、先用 SFT 冷启动、做奖励塑形。

## 三种方法其实是同一件事的不同加权

| 方法 | 如何利用采样到的轨迹 |
| --- | --- |
| REST | 只保留成功轨迹，做 SFT |
| REINFORCE | 用轨迹奖励缩放对数概率 |
| GRPO | 用组内相对优势缩放对数概率 |

它们都让模型在自己的轨迹上学习，区别只在于**如何给每个动作重新加权**。三者都针对 SFT 的三个缺陷：直接优化回报、能从失败中学习、训练分布与推理分布一致。

代价是必须真的在环境里试错：慢、贵，梯度噪声大。后续两讲会讨论稳定化与系统工程。

## 本讲结论

- SFT 优化的是「像演示」，RL 优化的是「拿到回报」。
- 策略梯度用对数概率的梯度乘奖励，绕开不可导的采样与环境。
- 基础 REINFORCE 对零奖励轨迹没有信号；优势函数让更新相对于预期表现。
- 减去只依赖历史的基线不引入偏差，只降低方差。
- GRPO 用同题多条 rollout 的均值当基线，省掉了单独的 value 模型。
- 组内没有成败差异时，GRPO 得不到任何学习信号。

## 理解检验

1. 用 number search 说明 SFT 的「任务错位」具体错在哪里。
2. 为什么减去基线不会让策略梯度产生偏差？
3. 在奖励全为二值的情况下，REINFORCE 与 REST 的更新有什么本质区别？
4. GRPO 为什么必须在同一道题内部计算均值，而不能跨题？
5. DR-GRPO 去掉标准差归一化的理由是什么？
