> **原书范围** 第 20 章（印刷页 531–548）

章首定义：数字图像处理是通过计算机对图像进行**去除噪声、增强、复原、分割、提取特征**等处理的方法和技术。它的发展受三个因素推动：计算机的发展、数学的发展（尤其离散数学理论的创立与完善）、农牧业/林业/环境/军事/工业/医学等应用需求的增长。本章只讲 Python 库函数的用法，不展开算法推导——这是全书最后一章，性质上更像「工具箱速查 + 四个应用案例」。

## 20.1 数字图像概述（p.531–538）

### 20.1.1 图像的概念及表示（p.531–533）

**1. 图像的概念**

图像按表现方式分两类：

- **连续图像**：二维坐标系中连续变化的图像，像素点无限稠密，且有灰度值（从暗到亮的变化值）。典型代表是光学透镜系统获取的照片（人物照、景物照），又称模拟图像。
- **离散图像**：用数字序列表示的图像，阵列中每个元素是数字图像的最小单位——**像素**。像素按某种规律编成系列二进制数码（0 和 1）表示图像上每个点的信息，故又称数字图像。

直观对照：胶片记录的照片是连续图像，数码相机拍的是离散图像。

**2. 图像的数字化采样**

计算机只能处理数字信号，连续图像必须数字化。把图像看作连续函数 $f(x,y)$，各点灰度是位置的函数，数字化要经过**采样**与**量化**两步。

采样是按图像空间坐标测量像素灰度值：对 $f(x,y)$ 等间隔采样，在 $(x,y)$ 平面上把图像分成均匀小网格，小网格位置用整数坐标表示，采样值即该网格位置的灰度值。若每行 $M$ 个像素、每列 $N$ 个像素，整幅图对应一个 $M\times N$ 数字矩阵，于是得到像素的两个属性：**位置**（由采样点两个坐标确定，对应网格行列）和**灰度**（明暗程度）。

量化是把仍是连续量的灰度值分成若干灰度等级（把光强度数字化）。图像经采样和量化后即得数字图像（图 20.1(a)），通常用矩阵表示（图 20.1(b)）：

$$
f(x,y)=\begin{bmatrix}f(0,0)&f(0,1)&\cdots&f(0,N-1)\\ f(1,0)&f(1,1)&\cdots&f(1,N-1)\\ \vdots&\vdots&&\vdots\\ f(M-1,0)&f(M-1,1)&\cdots&f(M-1,N-1)\end{bmatrix}
$$


图 20.1 数字图像的矩阵表示（原书 p.532）：(a) 为 Lena 人像（坐标原点在左上，$x$ 轴向下、$y$ 轴向右）；(b) 为对应的 $M\times N$ 矩阵。注意 (a) 中坐标轴方向与通常数学坐标系不同，这是图像处理的惯例——**行号对应 $x$（向下增大），列号对应 $y$（向右增大）**，读后面的 `crop`、`paste` 坐标时按这个约定理解。

矩阵元素即像素，每个像素有 $x$、$y$ 两个坐标和一个灰度值。以 256 级灰度为例，用 8 位（一个字节）表示，取值 0–255 对应由黑到白；只有黑白二值的图像用 1 位，0 和 1 表示黑白。

量化方法有等间隔与非等间隔两类。非等间隔量化要依据该图灰度值的概率密度函数，但概率分布因图而异，找不到普适最优公式，故实际应用一般采用**等间隔量化**。

**3. 图像类型**

按颜色和灰度的多少分四种基本类型。

1) 二值图像：二维矩阵仅由 0、1 构成，`0` 代表黑、`1` 代表白。每个元素仅两种可能，数据类型通常是一个二进制位。常用于文字、线条图的扫描识别（OCR）和掩膜图像存储。

2) 灰度图像：矩阵元素整数取值范围通常为 $[0,255]$，数据类型一般为 8 位无符号整数（`uint8`），即常说的 256 灰度图像。`0` 纯黑、`255` 纯白，中间整数由黑到白过渡。若为 `uint16` 类型，取值范围 $[0,65535]$；若为 `double` 类型，取值为浮点数，规定双精度归一化灰度图像取值范围 $[0,1]$，`0` 黑、`1` 白。二值图像可看作灰度图像的特例。

3) RGB 彩色图像：彩色像素的 $m\times n\times 3$ 数组，每个彩色像素点是特定空间位置上红、绿、蓝三个分量。也可看作三幅灰度图像形成的「堆」，送到显示器 RGB 输入端即产生彩色图像。三个分量图像分别称红、绿、蓝分量图像，其数据类型决定取值范围：`double` 为 $[0,1]$，`uint8` 为 $[0,255]$，`uint16` 为 $[0,65535]$。

4) 索引图像：两个分量——数据矩阵 $X$ 与彩色映射矩阵 `map`。`map` 是 $m\times3$、取值在 $[0,1]$ 的 `double` 数组，行数 $m$ 与所定义的颜色数目相等，每行定义一种颜色的红、绿、蓝分量。像素亮度值「直接映射」到彩色值：每个像素的颜色由 $X$ 的值作为指向 `map` 的指针决定。

这四类在后面的例子中逐一出现：`'L'` 模式对应灰度、`'RGB'` 与 `'RGBA'` 对应彩色、`convert('CMYK')` 是印刷四色。

### 20.1.2 数字图像处理涉及的 Python 库（p.533–538）

常用库有 OpenCV、PIL、skimage，本节只介绍前两个。

**1. OpenCV 库**

OpenCV 是基于 BSD 许可（开源）发行的跨平台计算机视觉库，可运行在 Linux、Windows、Android、Mac OS 上。它轻量高效，由一系列 C 函数和少量 C++ 类构成，同时提供 Python、Ruby、MATLAB 等语言接口；主要接口是 C++，但保留了大量 C 接口。

**例 20.1（OpenCV 读入、显示与保存，原书 p.534）**

```python
#程序文件Pex20_1.py
import cv2
img=cv2.imread("Lena.bmp")
cv2.imshow('image',img)
cv2.imwrite('Lena.jpg',img)
```

输入 `Lena.bmp`（未压缩位图），输出 `Lena.jpg`（JPEG 压缩）；中间在名为 `image` 的窗口显示。`imread` 默认以 BGR 顺序读入三通道，`imwrite` 按扩展名决定编码格式——**同一图像从 bmp 转 jpg 会有有损压缩，像素值不再逐点相同**，这一点在需要精确复现数值时要注意。

**例 20.2（视频逐帧存图，原书 p.534）**

```python
#程序文件Pex20_2.py
import cv2,os
os.mkdir("source")  #在当前目录下创建新目录source
video=cv2.VideoCapture("test.avi")
L=int(video.get(cv2.CAP_PROP_FRAME_COUNT))  #计算视频的帧数
for i in range(L-1):
    ret,frame=video.read()
    cv2.imshow('Frame',frame); cv2.waitKey(2)  #停顿2毫秒
    cv2.imwrite("source\\"+str(i)+".jpg",frame)
```

输入 `test.avi`（封底二维码），输出目录 `source` 下 `0.jpg`、`1.jpg`……直至 `L-2.jpg`。循环写 `range(L-1)` 而非 `range(L)`，最后一帧不会写出（原书未说明原因，可能与读帧返回 `False` 的边界有关）；`os.mkdir` 在目录已存在时会抛 `FileExistsError`，重复运行前需删目录或改用 `os.makedirs(..., exist_ok=True)`——**补充说明**。

`imshow` 之后必须在程序中销毁窗口，否则程序无法正常终止。两个函数：

- `cv2.destroyWindow(windows_name)`：销毁单个指定窗口，参数为字符串窗口名；
- `cv2.destroyAllWindows()`：销毁全部窗口，无参数。

销毁不能「窗口一出现就销毁」，否则看不到画面，需停顿一段时间，用 `cv2.waitKey`：

1. 让窗口停留一段时间后自动销毁；
2. 接收指定命令（如键盘敲击）后结束。

调用格式 `cv2.waitKey(parameter)`，`parameter = None & 0` 表示一直显示，除此之外表示显示的毫秒数。原书这句「`None & 0`」的写法是笔误式的表述，实际语义是「传 0 或空表示无限等待」——`waitKey(0)` 才是无限等待，`waitKey(2)` 是停 2 毫秒。

**2. 图像色彩空间变换 `cv2.cvtColor`**

有些图像在 RGB 空间的信息不如转换到其他空间清晰。常见色彩空间有 RGB、HLS、HSV、HSB、YCrCb、CIE XYZ、CIELAB 等，经常需要转换以便生成 mask 等操作，共 274 种转换类型。

```python
#程序文件Pz20_1.py
import cv2
flags = [i for i in dir(cv2) if i.startswith('COLOR_')]
print(flags)
```

列出所有 `COLOR_` 开头的常量，即可查全部转换类型。

**例 20.3（颜色转换，原书 p.535）**

```python
#程序文件Pex20_3.py
import matplotlib.pyplot as plt, cv2
img_BGR = cv2.imread('peppers.png')  # BGR (数据文件见封底二维码)
plt.subplot(3,3,1); plt.imshow(img_BGR)
plt.axis('off'); plt.title('BGR')
img_RGB = cv2.cvtColor(img_BGR, cv2.COLOR_BGR2RGB)
plt.subplot(3,3,2); plt.imshow(img_RGB)
plt.axis('off'); plt.title('RGB')
img_GRAY = cv2.cvtColor(img_BGR, cv2.COLOR_BGR2GRAY)
plt.subplot(3,3,3); plt.imshow(img_GRAY)
plt.axis('off'); plt.title('GRAY')
img_HSV = cv2.cvtColor(img_BGR, cv2.COLOR_BGR2HSV)
plt.subplot(3,3,4); plt.imshow(img_HSV)
plt.axis('off'); plt.title('HSV')
img_YcrCb = cv2.cvtColor(img_BGR, cv2.COLOR_BGR2YCrCb)
plt.subplot(3,3,5); plt.imshow(img_YcrCb)
plt.axis('off'); plt.title('YcrCb')
img_HLS = cv2.cvtColor(img_BGR, cv2.COLOR_BGR2HLS)
plt.subplot(3,3,6); plt.imshow(img_HLS)
plt.axis('off'); plt.title('HLS')
img_XYZ = cv2.cvtColor(img_BGR, cv2.COLOR_BGR2XYZ)
plt.subplot(3,3,7); plt.imshow(img_XYZ)
plt.axis('off'); plt.title('XYZ')
img_LAB = cv2.cvtColor(img_BGR, cv2.COLOR_BGR2LAB)
plt.subplot(3,3,8); plt.imshow(img_LAB)
plt.axis('off'); plt.title('LAB')
img_YUV = cv2.cvtColor(img_BGR, cv2.COLOR_BGR2YUV)
plt.subplot(3,3,9); plt.imshow(img_YUV)
plt.axis('off'); plt.title('YUV'); plt.show()
```

输入 `peppers.png`（彩椒图），输出 9 幅同图不同色彩空间的对比（图 20.2）。图 20.2 的读法：BGR 与 RGB 只是红蓝通道互换（肉眼看差异不大，但颜色偏冷/偏暖）；GRAY 只保留亮度；HSV/HLS 把色调与亮度分离，适合做颜色分割；YCrCb/LAB/YUV 多用于肤色检测与压缩。`plt.imshow` 默认按 RGB 解释数组，所以第一幅直接画 BGR 会偏色，这也正是要转 `COLOR_BGR2RGB` 的原因。

原书随后解释为何常转灰度：图像颜色主要来自外界光照，同一景物在不同光照下产生不同颜色；做特征提取和识别时要的是**梯度信息**（图像的本质内容），颜色反而干扰梯度提取，转灰度还能减少数据量、增强处理效果。这段是「为什么要灰度化」的动机说明，值得记住。

**2. PIL 库**

PIL（Python imaging library）提供通用的图像处理功能，以及大量基本图像操作：缩放、剪裁、旋转、颜色转换等。

**例 20.4（PIL 读入、保存、缩放/裁剪/旋转，原书 p.536）**

```python
#程序文件Pex20_4.py
from PIL import Image
from numpy import array
import pylab as plt  #加载Matplotlib的Pylab接口
a=Image.open("empire.jpg")
#返回一个PIL图像对象(数据文件见封底二维码)
b=a.convert("L")  #转换为灰度图像对象
b.save("empire2.jpg")
#把灰度图像保存到empire2.jpg (数据文件见封底二维码)
aa=array(a)  #把图像对象转换为数组
print(aa.shape)  #显示图像的大小
#左上角为坐标原点，下面裁剪左上右下指定区域
c=a.crop((100,100,400,400))
d=a.rotate(45)  #图像旋转45度
plt.rc('font',family="SimHei")
plt.subplot(221); plt.imshow(a); plt.title("原图")
plt.subplot(222); plt.imshow(b); plt.title("灰度图")
plt.subplot(223); plt.imshow(c); plt.title("剪裁图像")
plt.subplot(224); plt.imshow(d); plt.title("旋转图像")
plt.show()
```

输入 `empire.jpg`（帝国大厦，约 800×600），输出 `empire2.jpg`（灰度版）与四联图（图 20.3）。`crop((100,100,400,400))` 的四个数是左、上、右、下，裁出 300×300 的方块；`rotate(45)` 逆时针转 45°，**扩出的四角默认填黑**（图 20.3(d) 四角黑色）。图 20.3 里四幅图的坐标刻度从 0 到 800/500 不等，正是尺寸不同所致。

**例 20.5（图像轮廓与直方图，原书 p.538）**

```python
#程序文件Pex20_5.py
from PIL import Image
from numpy import array
import pylab as plt  #加载Matplotlib的Pylab接口
#下面读取图像到数组中
a=array(Image.open("empire.jpg").convert('L'))
plt.rc('font',size=16) #数据文件见封底二维码
plt.subplot(121); plt.contour(a,origin='image')  #轮廓图
plt.subplot(122); plt.hist(a.flatten(),128); plt.show()
```

直方图刻画像素值的分布：用一定数目的小区间指定像素值范围，每个小区间统计落入的像素数。`hist()` 的第二个参数指定小区间数目；**`hist()` 只接受一维数组，故画图前必须先用 `flatten()` 按行优先把数组转成一维**。图 20.4 为轮廓线与直方图：(a) 是等高线形式的轮廓（可以看成灰度的「地形图」，线条密集处是边缘），(b) 的直方图在 100–150 附近有个高峰，对应建筑主体亮度集中区。

## 20.2 PIL 库的模块介绍（p.538–542）

PIL 的功能模块有 `Image`、`ImageDraw`、`ImageFont`、`ImageFilter` 等，本节按模块举例。

**1. Image 模块（p.539–540）**

**例 20.6（读入、显示、保存）**

```python
#程序文件Pex20_6.py
from PIL import Image
a=Image.open('flower.jpg')  #读入图像(数据文件见封底二维码)
a.show()  #显示图片
print(a.mode, a.size, a.format) #显示图像信息
a.save("flower2.png")  #另存为另一文件(数据文件见封底二维码)
```

输入 `flower.jpg`，输出 `flower2.png`，并打印 `mode`（如 `RGB`）、`size`（宽×高）、`format`（`JPEG`）。`show()` 调用系统看图程序，不阻塞脚本。

**例 20.7（创建新图像）**

```python
#程序文件Pex20_7.py
from PIL import Image
a=Image.new("RGB",(640,480),(50,50,100))  #创建新图像
a.save("figure20_7.jpg") #保存图像
a.show() #显示图像
```

**注 20.1**：`RGB` 为图片模式 `mode`，`(640,480)` 为图片尺寸，`(50,50,100)` 为图片颜色。

注意 `Image.new` 的尺寸参数是 `(宽, 高)`，与数组形状 `(行, 列)` 顺序相反——用 `np.array(img).shape` 得到的是 `(480, 640, 3)`，换算时容易搞反。

**例 20.8（改变大小与模式）**

```python
#程序文件Pex20_8.py
from PIL import Image
from pylab import subplot,imshow,show
a=Image.open('flower.jpg')  #读入图像(数据文件见封底二维码)
b=a.resize((128,128))  #改变图像尺寸
c=b.convert('CMYK')  #转换为CMYK模式
subplot(121); imshow(b)
subplot(122); imshow(c); show()
```

输入 `flower.jpg`，输出 128×128 的 RGB 缩略图与同尺寸 CMYK 图。`convert('CMYK')` 是印刷四分色（青、品红、黄、黑），`imshow` 画四通道图时只显示前三个通道，所以右侧会显得偏色——这属于显示问题，不是转换错误。

**例 20.9（图像分割与合并）**

```python
#程序文件Pex20_9.py
from PIL import Image
from pylab import subplot,imshow,show
a=Image.open('flower.jpg')  #读入图像(数据文件见封底二维码)
ra,ga,ba=a.split()  #图像分割成R，G，B三个通道
c=Image.merge('RGB',(ra,ga,ba))  #三个通道合成一张彩色图像
subplot(221); imshow(ra); subplot(222); imshow(ga)
subplot(223); imshow(ba); subplot(224); imshow(c); show()
```

`split()` 返回三通道灰度图，`merge('RGB',(ra,ga,ba))` 重新合成，合成结果与原图逐像素相同——这是验证通道顺序是否正确的标准手法。注意此处变量命名 `ra,ga,ba` 对应 R、G、B，但 PIL 的通道顺序在内存中就是 R、G、B（与 OpenCV 的 BGR 不同），混用两个库时这是最常见的错色来源。

**例 20.10（图像粘贴）**

```python
#程序文件Pex20_10.py
from PIL import Image
a=Image.open('flower.jpg')  #读入图像(数据文件见封底二维码)
b=Image.open('logo.jpg')
print(a.size,b.size)  #显示图像的大小
c=b.resize((50,50))  #把图像缩小
a.paste(c,(20,20)); a.show()  #粘贴图像并显示
```

输入 `flower.jpg` 与 `logo.jpg`，输出在左上角 (20,20) 处贴了 50×50 logo 的花图。`paste` 直接覆盖（不做 alpha 混合），所以 logo 的透明通道在此不起作用——要与背景自然融合须用 `paste(..., mask=...)` 或 `alpha_composite`，见例 20.17、20.16。

**例 20.11（读取和设置指定位置的像素）**

```python
#程序文件Pex20_11.py
from PIL import Image
from numpy import array
a=Image.open('flower.jpg')  #读入图像(数据文件见封底二维码)
position=(100,100); b1=a.getpixel(position)  #读取像素
a.putpixel(position,tuple(array(b1)//2))  #修改像素
print(b1,a.getpixel(position))  #显示修改前后的像素值
```

`getpixel((100,100))` 返回该点的 RGB 三元组，`array(b1)//2` 把三个分量各自除以 2（变暗一半），`tuple(...)` 转回元组写回。输出为修改前后的两个三元组。注意 `(100,100)` 是 `(x, y)` 即 `(列, 行)`，与 numpy 索引 `[行, 列]` 相反。

**2. ImageDraw 模块（p.540–541）**

ImageDraw 提供基本图形绘制：直线、弧线、矩形、多边形、椭圆、扇形等。实现了一个 `Draw` 类，所有绘制功能都是 `Draw` 实例的方法。

- `line()` 需两个参数：第一为线段起点和终点，第二为颜色值；
- `arc()` 需四个参数：圆弧的左上角与右下角坐标、起始角度、结束角度、颜色值。

**例 20.12（线段与圆弧绘制）**

```python
#程序文件Pex20_12.py
from PIL import Image,ImageDraw
```

### 20.3.1 生成验证码图片（p.542–543）

背景：为防止爬虫自动提交表单、确保客户端是人在操作，网页用验证码增加提交难度、阻止搜索引擎抓取特定页面。

生成原理：随机生成若干字符绘制到图像中，再对背景或前景做「增加识别难度」的处理。措施有五：① 随机绘制不同颜色的背景点；② 用随机色绘制字符；③ 在图像中绘制随机线段；④ 对图片变形、模糊；⑤ 显示花、球等实物图像让操作者识别。

**例 20.15（生成图像验证码）**

```python
#程序文件Pex20_15.py
from PIL import Image,ImageDraw,ImageFont
from numpy.random import randint,random
def rndChar():  #产生随机字符
    s="abcdefghjkmnpqrstuwxyABCDEFGHJKMNPQRSTUWXY23456789@#$%&"
    #去除易混淆的字符
    return s[randint(0,len(s))]
def rndColor():  #生成随机颜色
    return tuple(randint(64,256,3))
w=50*6; h=60  #设置图像的宽度和高度
a=Image.new('RGB',(w,h),(255,255,255))
font=ImageFont.truetype("c:\\Windows\\Fonts\\simsun.ttc",48)
b=ImageDraw.Draw(a)  #创建Draw对象
def createLines(n):  #绘制干扰线
    for i in range(n):
        begin=(randint(0,w),randint(0,h))  #起始点
        end=(randint(0,w),randint(0,h))    #结束点
        b.line([begin,end],fill=rndColor(),width=2)
def createPoints(rate):  #绘制干扰点
    for x in range(w):
        for y in range(h):
            if random(1)<=rate:
                b.point((x,y),fill=rndColor())
def drawStr():  #绘制字符
    Str=''
    for t in range(6):
        Chr=rndChar(); Str=Str+Chr
        b.text((50*t+10,5),Chr,font=font,fill=rndColor())
    print(Str)
createLines(6); createPoints(0.15); drawStr()
a.show(); a.save("figure20_15.png")
```

输入：无（全部随机生成）；输出：`figure20_15.png`（300×60 的 6 位验证码，图 20.6），并在控制台打印答案 `Str`。三个环节分别对应上面措施 ③②①：`createLines(6)` 画 6 条宽 2 的干扰线；`createPoints(0.15)` 以 15% 概率逐像素撒点；`drawStr()` 逐字符写。

字符集刻意去掉了 `i`、`l`、`0`、`o` 等易混字符（`s` 里没有 `i`、`l`、`0`、`1`、`O`），这是验证码设计的通用做法。`rndColor()` 取 `randint(64,256,3)`，即每个分量不低于 64，保证颜色不会太暗以致看不清。

**补充（本次核对）**：`randint` 返回 `np.int64`，部分 PIL 版本对 `tuple` 中的 `np.int64` 会报类型错误，稳妥写法是 `tuple(int(v) for v in randint(64,256,3))`；坐标同理。图中 6 个字符的实际答案在扫描件上被干扰线遮挡，无法逐字确认，本笔记不转录图 20.6 的具体字符。

### 20.3.2 给图像添加水印（p.544–545）

数字水印是向多媒体数据（图像、声音、视频）中添加数字信息，用于**真伪鉴别、版权保护**。嵌入的水印隐藏于宿主文件，不影响原文件的可观性与完整性。分可见水印与不可见水印，网络图像多为可见水印，内容多为制作者所属机构的图标或字母缩写。

**例 20.16（添加文字水印）**

```python

                    #数据文件见封底二维码
```

### 20.3.3 生成二维码（p.545–547）

二维码（QR Code，quick response code，快速响应矩阵码）是二维条形码的一种，日本 Denso Wave 公司 1994 年发明。因可读性强、存储容量大而广泛应用：商品信息查询、社交好友互动、网络地址访问等。码由白色背景下黑色模块组成的正方形图案表示，可编码二进制数据、字符、数字乃至汉字。Python 下制作二维码的库是 `qrcode`，该库以 PIL 为基础。

**例 20.18（网络地址的二维码）**

```python
#程序文件Pex20_18.py
import qrcode
qr=qrcode.QRCode(
    version=1, #二维码的尺寸大小，取值范围为1-40
    error_correction=qrcode.constants.ERROR_CORRECT_L,
    box_size=10,  #二维码里每个格子的像素大小
    border=5  #边框的格子厚度，默认是4
)
qr.add_data("https://www.python.org/")  #设置二维码数据
qr.make(fit=True)  #启用二维码颜色设置
img=qr.make_image(fill_color="green", back_color="white")
img.show(); img.save("figure20_17.png")
#显示并保存二维码,见封底二维码
```

参数含义（原书 p.546）：

- `version`：尺寸大小，1–40。最小 1 生成 21×21 矩阵，每增加 1 尺寸增加 4，如 version=2 为 25×25。
- `error_correction`：容错系数，四档——`ERROR_CORRECT_L` 7% 字节码可容错、`M` 15%、`Q` 25%、`H` 30%。
- `box_size`：每个格子的像素大小。
- `border`：边框格子厚度，默认 4。

输出：绿色码点、白底的 python.org 网址二维码。**注意保存文件名仍是 `figure20_17.png`，与例 20.17 的水印图重名**，按原书顺序运行会覆盖前一张，属笔误（应为 `figure20_18.png`），见核对记录。

**例 20.19（生成带图标的二维码）**

思路：先生成高容错性（H 级）二维码，打开 logo 图片，把它的大小改为二维码大小的 1/16，再粘到二维码中心，最后保存。

```python
#程序文件Pex20_19.py
from PIL import Image
import qrcode
qr=qrcode.QRCode(
    version=2,
    error_correction=qrcode.constants.ERROR_CORRECT_H,
    box_size=10,
    border=1
)
qr.add_data("https://www.python.org/")
qr.make(fit=True)
img=qr.make_image().convert("RGBA")
w1,h1=img.size
factor=4; w2=w1//factor; h2=h1//factor
icon=Image.open("logo.jpg") #数据文件见封底二维码
w3,h3=icon.size
if w3>w2: w3=w2
if h3>w2: h3=h2
icon=icon.resize((w3,h3))  #更改图标的尺寸
w4=(w1-w3)//2; h4=(h1-h3)//2
img.paste(icon,(w4,h4))  #将图标粘贴到二维码的中心位置
img.show(); img.save("figure20_19.png")
```

输入 `logo.jpg`，输出带中心图标的二维码 `figure20_19.png`。用 H 级容错（30%）正是为了「中心被图标遮住一部分仍能扫出」，这是二维码加 logo 的通用前提。`if h3>w2: h3=h2` 的判断沿用了宽度阈值 `w2` 比较高度，应为 `h3>h2`，逻辑小瑕疵（本例 logo 接近正方，不影响结果）——见核对记录。

### 20.3.4 拼图问题（p.547–548）

**例 20.20（碎纸片的拼接复原，2013 年全国大学生数学建模竞赛 B 题附件 1）**

问题：给若干条纵向切开的碎纸片（`附件1\*.bmp`），要复原成完整的横向长条。

假设与变量：每张碎片高度相同、宽度相同；拼接只按「左右边界的像素差最小」判断；作为整体的一条纸带，最左/最右边界应是纯白（灰度 255）。

算法（原书描述）：

1. 读入第一张图并转为浮点型数组 `a`；把它的右边界像素 `L2` 与其余各图的左边界 `e1` 比较，把它的左边界 `L1` 与各图右边界 `e2` 比较，差最小者与之拼接。
2. 若某图左边界像素全为 255（纯白），说明它是整条拼接图的**最左端**，此时只能往右拼。
3. 若某图右边界全为 255，说明它是最右端，只能往左拼。
4. 依次类推，直到全部拼完。

```python
#程序文件Pex20_20.py
import glob, numpy as np
from PIL import Image
f = glob.glob("附件1\\*.bmp")  #读入附件1下所有bmp文件名称
n = len(f); a = np.array(Image.open(f[0]))
a = a.astype(float); jj = np.arange(1,n)
L1 = a[:,0]; L2 = a[:,-1]  #拼接的大图像左边界和右边界初始化
tind = [0]
cont_img = a
for i in range(n - 1):
    tcha1 = [];       tcha2 = []
    for j in jj:
        a2 = np.array(Image.open(f[j])).astype(float)
        e1 = a2[:, 0]; e2 = a2[:, -1]
        cha1 = abs(L1 - e2).sum(); cha2 = abs(L2 - e1).sum()
        tcha1.append(cha1) ; tcha2.append(cha2) #左右边界的差异
    m1 = np.array(tcha1).min(); m2 = np.array(tcha2).min()
    if abs(L1 - 255.).sum() < 1:
        ind = np.where(tcha2 == m2)
        tind=np.hstack((tind, jj[ind])) # 右拼接
        tt = np.array(Image.open(f[jj[ind[0][0]]])).astype(float)
        cont_img = np.hstack((cont_img, tt))
        L2 = tt[:, -1]; np.delete(jj, ind)
    elif abs(L2 - 255.).sum() < 1:
        ind = np.where(tcha1 == m1)
        tind = np.hstack((jj[ind], tind)) # 左拼接
        tt = np.array(Image.open(f[jj[ind[0][0]]])).astype(float)
        cont_img = np.hstack((tt,cont_img))
        L1 = tt[:, 0]; np.delete(jj, ind)
    elif m1 < m2:
        ind = np.where(tcha1 == m1)
        tind = np.hstack((jj[ind], tind)) # 左拼接
        tt = np.array(Image.open(f[jj[ind[0][0]]])).astype(float)
        cont_img = np.hstack((tt, cont_img))
        L1 = tt[:, 0]; np.delete(jj, ind)
    else:
        ind = np.where(tcha2 == m2)
        tind=np.hstack((tind, jj[ind])) # 右拼接
        tt = np.array(Image.open(f[jj[ind[0][0]]])).astype(float)
        cont_img = np.hstack((cont_img, tt))
        L2 = tt[:, -1]; np.delete(jj, ind)
print(tind)  #显示各个图像的拼接排列次序
Image.fromarray(cont_img).show()
```

输出：`tind`（碎片的排列次序）与拼好的整幅图。逻辑分四支：左边界全白→只能右拼；右边界全白→只能左拼；否则比较「当前左边界与候选右边界」的差 `m1` 和「当前右边界与候选左边界」的差 `m2`，谁小就往哪边拼。

**本次核对（未运行）**：这段代码按原书照录，逻辑上有三处隐患，实际运行前需修正：

1. `np.delete(jj, ind)` 的返回值没有赋回 `jj`，`jj` 不会缩短，同一碎片可能被重复选中（原书依赖「差值为 0 的唯一匹配」掩盖了这个问题）。
2. `tind=np.hstack((tind, jj[ind]))` 中 `tind` 是 1 维、`jj[ind]` 也是 1 维，`hstack` 可行；但后面 `tind` 与 2 维数组混用时需检查维度。
3. 每轮内层循环都重新 `Image.open` 读全部碎片，效率很低（$n$ 个碎片要读 $n^2$ 次）；应先把所有图读成数组缓存。

因为是扫描件且附件数据需从封底二维码下载，本次未实际运行，故不给「拼接结果正确」的结论，只记录算法与代码。
