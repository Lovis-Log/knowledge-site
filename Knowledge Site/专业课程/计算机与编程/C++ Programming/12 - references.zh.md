## 三点区别

### 一、引用不需要解引用

```cpp
double double_value {12.34};
double& ref_double_value {double_value};   // 引用
double* p_double_value {&double_value};    // 指针

// 读
std::cout << double_value << std::endl;      // 12.34
std::cout << ref_double_value << std::endl;  // 12.34
std::cout << *p_double_value << std::endl;   // 12.34（必须解引用）

// 写
ref_double_value = 20.0;      // 直接赋值
*p_double_value = 30.0;       // 必须解引用
```

引用在使用上就像原变量本身：读它、写它、取地址，都和原变量等价。指针则始终需要区分「地址」与「地址上的值」。

```cpp
std::cout << p_double_value << std::endl;   // 打印地址
std::cout << ref_double_value << std::endl; // 打印值
```

### 二、引用不能改绑

```cpp
double other_value {78.45};
ref_double_value = other_value;   // 这是赋值，不是改绑！
```

这一行不会让 `ref_double_value` 改为引用 `other_value`。它把 `other_value` 的**值**赋给 `ref_double_value` 所引用的 `double_value`。结果：

- `double_value` 变成 78.45；
- `ref_double_value` 仍然绑定 `double_value`；
- 两者地址都没有变。

C++ 没有语法可以在初始化之后让引用改绑。唯一的机会就是声明的那一刻，**这也解释了为什么引用必须初始化**：如果允许声明时不初始化，这个引用将永远无法绑定到任何对象，毫无用处。编译器直接拒绝：

```text
error: reference variable 'ref' requires an initializer
```

指针没有这个限制：

```cpp
double* p {&double_value};
p = &other_value;          // 合法：指针改为指向另一个变量
```

### 三、引用像「const 指针」

把两者放在一起看：

| 行为 | 引用 `T&` | 指针 `T*` |
| --- | --- | --- |
| 声明时是否必须初始化 | 必须 | 不必（但不初始化很危险） |
| 能否改绑到其他对象 | 不能 | 能 |
| 使用是否需要 `*` | 不需要 | 需要 |
| 能否为空 | 不能 | 能（`nullptr`） |

「不能改绑」正是 `T* const` 的性质，所以引用常被描述为「自动解引用的 const 指针」。

## `const` 引用

```cpp
int age {27};
int& ref_age {age};              // 可写引用
const int& cref_age {age};       // 只读引用

ref_age++;                        // 合法，age 变成 28
cref_age++;                       // 编译错误
```

`const` 引用承诺：**通过这个名字不能修改原对象**。注意它并不要求原对象本身是 `const`：

```cpp
const int& cref_age {age};   // age 是非 const 的
age = 30;                    // 合法，直接修改原变量
// cref_age 读出来就是 30
```

也就是说，`const` 限制的是「这个别名能不能写」，而不是「原对象能不能变」。这一点在函数参数里非常重要：`const T&` 表示「我要读你，但不会改你」，调用方不必担心副作用，也不必复制。

### 用指针模拟引用

引用的行为等价于「指向 const 的 const 指针」：

```cpp
const int* const p_age {&age};
```

两个 `const` 分别限制两件事：

- 左边的 `const`：不能通过 `*p_age` 修改 `age`；
- 右边的 `const`：不能让 `p_age` 指向别处。

于是 `*p_age = 30;` 和 `p_age = &other;` 都会编译失败，行为与 `const int&` 一致。这也说明引用并非新机制，只是把这两种限制打包成了一个更简洁的语法。

顺带一提：`const int& const` 是非法的——引用本身没有「顶层 const」可言，因为它从来就不能改绑，再加一个 `const` 没有意义。

## 什么时候用哪个

- **函数参数**：只读传参用 `const T&`，需要修改用 `T&`。避免拷贝，语义清晰。
- **必须「没有对象」时**：用指针，`nullptr` 表达「没有」。引用无法表达空。
- **需要改指向时**：用指针。
- **数组/动态内存**：天然用指针。

一句话：**优先用引用，只有在需要「可空」或「可改绑」时才退回指针。**

> **一句话总结：** 引用是必须初始化、不能改绑、无需解引用的别名；对引用赋值是改值不是改绑；`const T&` 只是禁止通过别名写入，与对象本身是否可变无关。

## 本章结论

- 引用是已有对象的别名，声明时必须初始化，之后不能改绑。
- 读写引用不需要 `*`，写法与原变量一致。
- 对引用赋值只修改被引用对象的值，不会改变绑定关系。
- 指针可以改绑、可以为空，但使用时要区分地址与值。
- `const T&` 禁止通过引用修改对象，但不要求对象本身是 `const`。
- 引用等价于 `const T* const`；不存在 `const T& const`。

## 理解检验

**1. 引用与指针的三点主要区别是什么？**

参考答案：第一，使用引用不需要解引用符号，读写方式与原变量一致；指针必须用 `*` 取值、`&` 取地址。第二，引用在初始化之后不能改绑到另一个对象，指针可以重新赋值指向别处。第三，声明引用时必须初始化，否则编译失败；指针可以先声明后赋值（但未初始化的指针是危险的）。

**2. 执行 `ref = other;` 会发生什么？为什么这不是「改绑」？**

参考答案：这是把 `other` 的值赋给 `ref` 所引用的对象，等价于 `original = other;`；`ref` 仍然绑定 `original`，两者的地址都不变。C++ 的引用在初始化时就固定了绑定，之后没有语法可以改变它——唯一的机会是声明那一刻。想验证这一点，可以打印 `&original` 与 `&ref`，赋值前后地址完全相同。

**3. 为什么引用必须在声明时初始化？**

参考答案：因为初始化是引用绑定对象的唯一机会。若允许声明时不初始化，这个引用就永远无法指向任何对象，之后任何使用都无意义，编译器因此直接拒绝。指针不同：它可以先为空、之后再赋值，所以不强制初始化（尽管实践中也应初始化）。

**4. `const int& cref = age;` 中 `age` 不是 `const`，这合法吗？此时能否通过 `age` 修改它？**

参考答案：合法。`const` 加在引用上，限制的是「通过 `cref` 这个名字不能写」，并不要求被引用的对象本身是 `const`。`age` 仍然可以被直接赋值，例如 `age = 30;`；之后通过 `cref` 读出来就是 30。所以 `const T&` 的准确含义是「只读别名」，而不是「只读对象」。

**5. `const int* const p = &age;` 中的两个 `const` 分别限制什么？它为什么能模拟引用？**

参考答案：左边的 `const` 修饰 `int`，表示不能通过 `*p` 修改 `age`；右边的 `const` 修饰指针本身，表示不能让 `p` 指向别处。两者合起来正好对应引用的两个性质：不能通过别名写原对象、不能改绑。再加上引用自动解引用，所以 `const T&` 在行为上等价于 `const T* const`。

**6. 一个函数参数应该用 `T`、`T&` 还是 `const T&`？**

参考答案：需要就地修改调用方对象时用 `T&`；只读且对象较大、不想复制时用 `const T&`；对象很小（如 `int`、`double`、指针）且只读时，直接按值 `T` 也很合理，复制成本低于间接访问的成本。需要表达「可能没有对象」时改用指针 `T*`，因为引用无法为空。
