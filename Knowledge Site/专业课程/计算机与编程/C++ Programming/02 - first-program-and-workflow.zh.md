## 注释

注释是写给人看的，编译器会完全忽略。

```cpp
// 单行注释：从 // 到行尾

/*
   块注释：
   可以跨多行
*/

int main() {
    std::cout << "Hello World" << std::endl; // 也可以写在语句后面
    return 0;
}
```

一个必须记住的限制：**块注释不能嵌套**。`/* ... /* ... */ ... */` 会在第一个 `*/` 处结束，后面的内容被当成代码，产生一堆莫名其妙的编译错误。

注释要克制。课程的说法很直白：注释太多会把程序变成小说。好的注释解释"为什么这样做"，而不是重复代码已经说清楚的事情。

## 三类问题

把代码变成可执行文件的过程里，问题只可能出现在三个位置：

| 类型 | 出现时机 | 后果 | 例子 |
| --- | --- | --- | --- |
| 编译期错误 | 编译时 | 不生成二进制 | 漏写分号、变量未声明 |
| 警告 | 编译时 | 仍然生成二进制 | 整数除以 0、隐式窄化 |
| 运行期错误 | 运行时 | 结果错误，或程序崩溃 | 除以 0 后使用结果 |

### 编译期错误

```cpp
std::cout << "Hello World" << std::endl   // 漏了分号
return 0;
```

编译器会报 `expected ';' before 'return'`。这类错误的特征是：**构建失败，没有可执行文件**。这其实是好事——编译器在问题进入运行阶段之前就拦住了它。

### 警告

```cpp
int value = 7 / 0;   // 编译通过，但给出警告
```

gcc 会警告 "division by zero"，构建仍然成功。警告不是装饰：它说明代码里存在一个编译器认为可疑的地方，通常应该修掉，而不是忽略。

### 运行期错误

把上面的除法结果打印出来：

```cpp
int value = 7 / 0;
std::cout << value << std::endl;
```

程序可能直接异常终止。整数除以零在 C++ 里是未定义行为，编译器不做强制检查，运行时就可能崩。所谓"运行期错误"，就是编译阶段看不出来、跑起来才发现的问题。

> **一句话总结：** 编译期错误让你拿不到程序，警告让你拿到一个有隐患的程序，运行期错误让你拿到一个会出错的程序。

## 语句

语句是程序的基本执行单位，以分号结束，**按从上到下的顺序执行**。

```cpp
int first_number {3};      // 语句 1
int second_number {7};     // 语句 2
int sum = first_number + second_number;   // 语句 3
std::cout << sum << std::endl;            // 语句 4
```

漏掉任意一个分号，都会变成编译期错误。一条语句可以跨行书写，编译器只认分号，不认换行。

多语句函数体的最后一个右花括号表示 `main` 结束；`main` 结束意味着程序结束，返回值交给操作系统。

## 函数

函数是一个可以反复调用的代码块：给它输入（参数），它返回输出（返回值）。

```cpp
int add_numbers(int first, int second) {
    int result = first + second;
    return result;
}
```

四个组成部分：

- **返回类型**：`int`，表示返回一个整数。
- **函数名**：`add_numbers`。
- **参数列表**：`(int first, int second)`，每个参数都要写类型。
- **函数体**：花括号内部，以 `return` 结束并交出结果。

调用：

```cpp
int main() {
    int sum = add_numbers(25, 7);
    std::cout << sum << std::endl;   // 32
    std::cout << add_numbers(3, 42) << std::endl;  // 45
    return 0;
}
```

两条规则必须记住：

1. **函数必须先定义（或先声明）再使用**。把 `add_numbers` 放到 `main` 后面而不声明，会直接编译失败。
2. **参数是值传递**：调用时把 `25` 和 `7` 复制给 `first`、`second`，函数内部改的是副本。

把加法从 `main` 搬到函数里，换来的是复用：换个数字再调用一次即可，不必复制粘贴整段逻辑。

## 输入输出流

C++ 把输入输出统一建模成**流**：数据沿着一条管道流动。

### 输出：cout、cerr、clog

```cpp
std::cout << "Hello C++20" << std::endl;
std::cerr << "Something went wrong" << std::endl;
std::clog << "A log message" << std::endl;
```

三者都使用 `<<`，区别在用途：

| 流 | 用途 |
| --- | --- |
| `std::cout` | 普通输出 |
| `std::cerr` | 错误信息，不带缓冲 |
| `std::clog` | 日志信息，带缓冲 |

不少终端会把 `cerr` 显示成红色，这就是"用不同的流表达不同的意图"的价值。目前只需知道它们都通向终端。

箭头方向也值得注意：`cout` 的 `<<` 指向左边，表示数据从程序流向流对象；`cin` 的 `>>` 指向右边，表示数据从流对象进入变量。

### 输入：cin

```cpp
int age {0};
std::string name;

std::cout << "Please type your name and age: " << std::endl;
std::cin >> name >> age;

std::cout << "Hello " << name << ", you are " << age << " years old" << std::endl;
```

`cin >> name >> age` 演示了链式输入：一次读入两个值，按空格分隔。需要 `#include <string>` 才能使用 `std::string`。

### 带空格的输入：getline

`cin >>` 遇到空格就停止。输入 `Daniel Gakwaya` 时，`name` 只会拿到 `Daniel`，剩下的 `Gakwaya` 会被当成年龄，程序随即错乱。

解决办法是 `std::getline`，它读到换行为止：

```cpp
std::string full_name;
std::cout << "Please type your full name: ";
std::getline(std::cin, full_name);
```

参数是"从哪个流读"和"存到哪个变量"。之后再用 `cin >> age` 读年龄即可。

> **补充：** 混用 `cin >>` 和 `getline` 时有个经典陷阱：`cin >>` 会把换行符留在缓冲区，紧接着的 `getline` 立刻读到空行。常见修法是先 `std::cin.ignore()` 吃掉残留的换行。本章还没涉及，但值得先记住。

## 程序是怎样运行的

课程给了一个简化模型，足以解释后面要讲的内存、指针与函数调用。

1. 编译器把 `main.cpp` 变成二进制 `rooster.exe`，存放在硬盘上。
2. 运行时，操作系统把二进制**整体载入内存（RAM）**。
3. CPU 从 `main` 的第一条语句开始，逐条执行。
4. 遇到变量声明，CPU 在内存里划一块空间并写入初始值。
5. 遇到函数调用，CPU 记下**返回地址**，跳到函数所在的位置执行，执行完再跳回来。

举例：

```cpp
int add_numbers(int a, int b) { return a + b; }

int main() {
    int a {10};
    int b {5};
    int c;
    std::cout << "Statement 1" << std::endl;
    c = add_numbers(a, b);
    std::cout << "Statement 2" << std::endl;
    return 0;
}
```

执行 `c = add_numbers(a, b)` 时，CPU 先把返回地址存起来，再跳到函数体：把 `10`、`5` 分别放进参数 `a`、`b`，相加得到 `15`，把结果交回 `c`，然后跳回原来的位置继续。

这个模型解释了两件事：

- 未初始化的 `int c;` 里是**垃圾值**——那块内存只是被划出来，没人写过它。
- 函数调用有成本：跳转、传参、保存返回地址。编译器可能把简单函数**内联**，即在调用点直接展开，省掉跳转。理解内存模型才能理解这类优化。

## 核心语言、标准库与 STL

三个词经常被混用，课程专门区分：

| 名称 | 含义 | 例子 |
| --- | --- | --- |
| 核心语言 | C++ 语法与基本类型，规则本身 | `int`、函数定义规则、语句、作用域 |
| 标准库 | 现成的高质量组件，随编译器提供 | `iostream`、`string`、`vector` |
| STL | 标准库中处理"容器 + 算法 + 迭代器"的那部分 | `std::vector`、`std::sort`、迭代器 |

`iostream` 属于标准库；写 `int` 属于使用核心语言；`std::vector` 与 `std::sort` 属于 STL。这个区分在查文档时很有用：查核心语言问题看语法规范，查 `setw` 这类工具看标准库文档。

## 本章结论

- 注释用 `//` 与 `/* */`，块注释不能嵌套。
- 问题分三类：编译期错误（拿不到程序）、警告（能编译但有隐患）、运行期错误（运行才出错）。
- 语句以分号结尾，按顺序执行；函数有返回类型、名字、参数和函数体，必须先定义后使用。
- `cout`/`cerr`/`clog` 是三条输出流，`cin` 是输入流；带空格的输入用 `getline`。
- 程序被载入内存后由 CPU 逐条执行；函数调用要保存返回地址，因此有成本。
- 核心语言、标准库、STL 是三个层次，不要混为一谈。

## 理解检验

**1. 编译期错误和警告都会在编译阶段出现，为什么课程说前者"更好"？**

参考答案：编译期错误会阻止生成可执行文件，问题被迫在运行前解决；警告则允许程序生成并运行，隐患被带进了运行阶段。前者的失败是确定的、可定位的，后者的失败取决于输入和运行环境，可能很久以后才暴露。所以"编译不过"在工程上往往比"带着警告上线"更安全。

**2. 为什么块注释不能嵌套？写出 `/* a /* b */ c */` 的实际解析结果。**

参考答案：注释由词法分析器按"遇到 `*/` 就结束"处理，不做括号配对。上面这段在第一个 `*/` 处结束，注释内容只有 `a /* b`；剩下的 ` c */` 被当作代码，其中 `c` 是未声明的标识符、`*/` 是非法记号，于是产生编译错误。

**3. 把 `add_numbers` 的定义放到 `main` 之后、且不在前面声明，会发生什么？为什么？**

参考答案：编译失败，报"`add_numbers` was not declared in this scope"一类错误。C++ 按从上到下的顺序处理源文件，编译到 `main` 里的调用时还没有见过这个名字，无法确定参数与返回类型。解决办法是在 `main` 之前放函数声明 `int add_numbers(int, int);`，或者直接把定义移到前面。

**4. `cin >> name` 输入 `Daniel Gakwaya` 之后，`name` 里是什么？接下来的 `cin >> age` 会得到什么？**

参考答案：`name` 只得到 `Daniel`，因为 `>>` 以空白字符为分隔，遇到空格就停止。缓冲区里还留着 ` Gakwaya\n`，接下来的 `cin >> age` 试图把 `Gakwaya` 解析成整数，解析失败，`age` 保持原值（C++11 起失败时会被置为 0），后续的输入也会失效。正确做法是用 `std::getline(std::cin, name)` 读取整行。

**5. 未初始化的 `int c;` 为什么可能含有"垃圾值"？这和内存模型有什么关系？**

参考答案：声明 `int c;` 只是让编译器在栈上划出 4 个字节，并没有写入任何值。那块内存之前可能被别的函数用过，残留着旧数据，所以读出来是一个没有意义的数。传统内存模型里局部变量不会自动清零（`static` 变量和全局变量才会），因此必须显式初始化，例如 `int c{};` 或 `int c = 0;`。

**6. 函数调用为什么有成本？编译器用什么手段降低这个成本？**

参考答案：调用时要保存返回地址、把实参复制到形参、跳转到函数代码，执行完再跳回原位置，这些都需要指令和时间。编译器可以把短小、频繁调用的函数**内联**：把函数体直接展开到调用点，省掉跳转和返回。课程的内存模型正是理解内联的前提——只有看到"跳转"这一步，才知道内联省掉的是什么。
