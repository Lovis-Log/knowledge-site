## 算术运算

```cpp
int number1 {2};
int number2 {7};
int result {0};

result = number1 + number2;   // 9
result = number2 - number1;   // 5
result = number1 - number2;   // -5
result = number1 * number2;   // 14
```

这些都是整数运算，结果仍然是整数。

### 整数除法：截断而不是四舍五入

```cpp
result = number2 / number1;   // 7 / 2
std::cout << result << std::endl;   // 3
```

`7 / 2` 得到 3，不是 3.5。原因是右边两个操作数都是 `int`，结果是 `int`，只能保留整数部分。可以理解为"2 能完整装进 7 几次"——三次，剩下的 1 被丢掉。

想要小数结果，至少让一个操作数是浮点数：

```cpp
double quotient = 7.0 / 2;   // 3.5
```

`7 / 2.0`、`7.0 / 2`、`7.0 / 2.0` 都行，编译器会把另一个也提升为 `double` 再相除。

### 取模：余数

```cpp
result = number2 % number1;   // 7 % 2
std::cout << result << std::endl;   // 1
```

`%` 求的是整数除法的余数。$31 \div 10 = 3$ 余 1，所以 `31 % 10` 等于 1。

取模只对整数有意义。`7.5 % 2` 编译不过——浮点数的"余数"没有公认定义，C++ 直接用 `std::fmod` 处理。

常见用途：判断奇偶（`n % 2 == 0`）、循环取模做环形索引（`index % size`）、提取十进制各位（`n % 10` 取个位）。

## 优先级与结合性

一个表达式里有多个运算符时，需要两条规则：

- **优先级（precedence）**：不同运算符谁先算。`*`、`/`、`%` 高于 `+`、`-`。
- **结合性（associativity）**：同优先级时从左还是从右算。加减乘除都是从左到右。

看这个表达式：

```cpp
int a {6}, b {4}, c {6}, d {9}, e {3}, f {2}, g {5};

int result = a + b * c - d / e - f + g;
```

按规则拆解：

1. 先算乘除：`b * c = 24`，`d / e = 3`。
2. 表达式变成 `a + 24 - 3 - f + g`，即 `6 + 24 - 3 - 2 + 5`。
3. 从左到右：`6+24=30`，`30-3=27`，`27-2=25`，`25+5=30`。

结果 30。

与之相关的优先级顺序（从高到低）：

| 优先级 | 运算符 | 结合性 |
| --- | --- | --- |
| 高 | 后缀 `++` `--` | 左 |
| | 前缀 `++` `--`、一元 `+` `-` | 右 |
| | `*` `/` `%` | 左 |
| | `+` `-` | 左 |
| | `<<` `>>` | 左 |
| | `<` `<=` `>` `>=` | 左 |
| | `==` `!=` | 左 |
| | `&&` | 左 |
| 低 | `||` | 左 |
| 最低 | 赋值 `=` `+=` 等 | 右 |

### 用括号表达意图

```cpp
int result = a + (b * c) - (d / e) - f + g;   // 同样是 30
```

结果相同，但读代码的人不用查表就知道先算什么。课程的建议很明确：**不要过度依赖优先级表，用括号把意图写出来**。

括号更大的作用是**改变**运算顺序：

```cpp
int result = (a + b) * c - d / e - f + g;
// (6+4)*6 - 3 - 2 + 5 = 60
```

现在加法先做，结果从 30 变成 60。

## 自增与自减

`++` 加 1，`--` 减 1。它们只能加减 1，不能加减 5 或 7。

### 后缀：先用后改

```cpp
int value {5};
std::cout << value++ << std::endl;   // 5
std::cout << value << std::endl;     // 6
```

`value++` 先取出当前值参与运算（这里是打印），语句结束后才把 `value` 加 1。所以第一行打印 5，第二行打印 6。

`value--` 同理：

```cpp
int value {5};
std::cout << value-- << std::endl;   // 5
std::cout << value << std::endl;     // 4
```

### 前缀：先改后用

```cpp
int value {5};
std::cout << ++value << std::endl;   // 6
std::cout << value << std::endl;     // 6
```

`++value` 先把 `value` 加 1，再取出新值参与运算，所以两行都打印 6。

记忆方法：**符号在后，旧值先出场；符号在前，新值先出场。**

单独写一行时（`value++;` 或 `++value;`），两者效果相同，只有把表达式的结果拿去用时才有区别。

## 复合赋值

`+=`、`-=`、`*=`、`/=`、`%=` 把"运算"和"赋值"合成一步：

```cpp
int value {45};

value += 5;    // 等价于 value = value + 5;  → 50
value -= 5;    // 等价于 value = value - 5;  → 45
value *= 2;    // 等价于 value = value * 2;  → 90
value /= 3;    // 等价于 value = value / 3;  → 30
value %= 11;   // 等价于 value = value % 11; → 8
```

最后一步验证：$30 \div 11 = 2$ 余 8，所以结果是 8。

复合赋值不是必需的语法糖，但它把"对同一个变量做累积运算"这个意图写得更紧凑，读起来也更清楚。

## 关系运算符

关系运算符比较两个值，结果是 `bool`：

| 运算符 | 含义 |
| --- | --- |
| `<` | 小于 |
| `<=` | 小于或等于 |
| `>` | 大于 |
| `>=` | 大于或等于 |
| `==` | 等于 |
| `!=` | 不等于 |

```cpp
int number1 {45};
int number2 {60};

std::cout << std::boolalpha;
std::cout << "number1 < number2: " << (number1 < number2) << std::endl;   // true
std::cout << "number1 > number2: " << (number1 > number2) << std::endl;   // false
std::cout << "number1 == number2: " << (number1 == number2) << std::endl; // false
std::cout << "number1 != number2: " << (number1 != number2) << std::endl; // true
```

### 为什么必须加括号

把括号去掉：

```cpp
std::cout << "number1 < number2: " << number1 < number2 << std::endl;
```

这段**编译不过**。原因在上一节的优先级表：`<<` 的优先级高于 `<`，编译器会先算 `(std::cout << ... << number1)`，再拿它的结果去和 `number2` 比较——而 `std::cout` 没有定义 `<`，于是报错。

加括号 `(number1 < number2)` 先把比较算成一个 `bool`，再交给 `cout` 输出。

### `=` 与 `==`

```cpp
if (number1 = number2) { }    // 赋值，不是比较
if (number1 == number2) { }   // 比较
```

单等号是赋值，双等号才是比较。`if` 里写单等号通常还能编译（赋值表达式的值被当作条件），但逻辑完全错了。有些编译器会给出警告，不要忽略它。

## 逻辑运算符

逻辑运算符作用于布尔值：

| 运算符 | 名称 | 何时为真 |
| --- | --- | --- |
| `&&` | 与 | 两个操作数都为真 |
| `\|\|` | 或 | 至少一个为真 |
| `!` | 非 | 操作数为假 |

真值表：

| a | b | a && b | a \|\| b |
| --- | --- | --- | --- |
| false | false | false | false |
| false | true | false | true |
| true | false | false | true |
| true | true | true | true |

```cpp
bool a {true}, b {false}, c {true};

std::cout << (a && b) << std::endl;      // false
std::cout << (a && c) << std::endl;      // true
std::cout << (a && b && c) << std::endl; // false（只要有一个 false 就 false）

std::cout << (a || b) << std::endl;      // true
std::cout << (!a) << std::endl;          // false
std::cout << (!b) << std::endl;          // true
```

`a && b && c` 说明"与"可以链式使用：**只要有一个假，整个表达式就是假**；"或"则相反，只要有一个真就是真。

### 与关系运算符组合

关系运算的结果是 `bool`，逻辑运算接收的正是 `bool`，所以可以自然组合：

```cpp
int d {45}, e {20}, f {11};

bool result = (d > e) && (d > f);   // true && true → true
```

括号同样重要：它既避免优先级问题，也让意图清楚。

> **补充：** `&&` 与 `||` 有"短路"行为：`a && b` 在 `a` 为假时不再计算 `b`，`a || b` 在 `a` 为真时不再计算 `b`。这在右边有副作用（比如函数调用）时非常关键，后面讲条件与循环时会经常用到。

## 本章结论

- `7 / 2` 得 3：整数除法截断，不四舍五入；要小数就让一个操作数变成浮点数。
- `%` 求余数，只对整数有意义。
- 乘除优先于加减；同优先级从左到右；括号可以改变顺序，也应当用来表达意图。
- `value++` 先用后加，`++value` 先加后用。
- `+=`、`-=`、`*=`、`/=`、`%=` 把运算与赋值合成一步。
- 关系运算得到 `bool`；打印比较结果时必须加括号，因为 `<<` 的优先级更高。
- `&&` 全真才真，`||` 一真即真，`!` 取反；它们可以链式组合，也可以接在关系运算后面。

## 理解检验

**1. `7 / 2` 和 `7.0 / 2` 分别得到什么？为什么？**

参考答案：`7 / 2` 得到 `3`（`int`），`7.0 / 2` 得到 `3.5`（`double`）。整数除法中两个操作数都是 `int`，结果类型也是 `int`，小数部分被直接丢弃，只保留"2 能装进 7 三次"。只要有一个操作数是浮点数，另一个就会被提升为 `double`，除法按浮点规则进行，保留小数。

**2. 计算 `6 + 4 * 6 - 9 / 3 - 2 + 5`，并写出每一步依据的优先级规则。**

参考答案：先乘除（优先级高于加减）：`4 * 6 = 24`，`9 / 3 = 3`（整数除法，恰好整除）。表达式变为 `6 + 24 - 3 - 2 + 5`。加减同级、左结合，从左到右依次计算：`6+24=30`，`30-3=27`，`27-2=25`，`25+5=30`。结果 30。

**3. `std::cout << (a < b);` 去掉括号后为什么编译失败？**

参考答案：`<<` 的优先级高于 `<`。去掉括号后表达式被解析为 `((std::cout << ...) < b)`：先执行流插入，而流插入表达式的结果类型是 `std::ostream&`，C++ 没有为 `std::ostream` 定义与整数比较的 `<` 运算符，因此编译报错。加上括号后，比较先算出一个 `bool`，再交给 `cout`，类型正确。

**4. `int v = 5; int a = v++; int b = ++v;` 之后，`v`、`a`、`b` 各是多少？**

参考答案：`v++` 先把旧值 5 交给 `a`，再把 `v` 加 1，所以 `a = 5`、`v = 6`；接着 `++v` 先把 `v` 加到 7 再交给 `b`，所以 `b = 7`、`v = 7`。最终 `v = 7`、`a = 5`、`b = 7`。口诀是"符号在后用旧值，符号在前用新值"。

**5. `value += 5` 与 `value = value + 5` 完全等价吗？为什么课程仍然推荐前者？**

参考答案：对内置整数类型，两者语义相同，结果一样。课程推荐 `+=` 是因为它把"在自身基础上累加"这个意图压缩成一个符号，读起来更直接，也不容易在长表达式里写错变量名。对自定义类型（后面讲的类），`+=` 还可以避免一次不必要的临时对象，不过那是后续内容。

**6. 写出 `a`、`b`、`c` 分别为 true、false、true 时，`(a && b) || (!c)` 的值，并说明计算过程。**

参考答案：先算括号内：`a && b` 中 `b` 为 false，结果为 false；`!c` 中 `c` 为 true，取反为 false。再算 `false || false`，结果为 **false**。整个表达式只有当"a 与 b 同时为真"或"c 为假"时才成立，本例两者都不满足。
