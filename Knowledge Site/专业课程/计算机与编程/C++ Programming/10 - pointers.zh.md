## 指针：保存地址的变量

```cpp
int* p_number {};            // 空指针，等价于 int* p_number {nullptr};
double* p_fractional {};
```

`int*` 读作「指向 int 的指针」。它存放的不是整数，而是某个 `int` 变量在内存中的地址。

### 空指针

`{}` 或 `nullptr` 表示「不指向任何有效对象」。它的意义是给指针一个确定的初始状态，避免里面是随机地址。**不要解引用空指针**——那是在访问一个明确无效的地址。

### 所有指针大小相同

```cpp
std::cout << "sizeof(int*) : " << sizeof(int*) << std::endl;
std::cout << "sizeof(double*) : " << sizeof(double*) << std::endl;
```

在本机两者都是 8 字节。原因是它们存的都是内存地址，而同一台机器上地址的宽度是固定的（64 位系统为 64 位）。指针指向什么类型，只影响编译器如何解释那块内存，不影响指针自身的大小。

### `*` 的位置与逗号声明

```cpp
int* p_a;     // 讲者偏好
int *p_b;     // 也可以
int * p_c;    // 也可以
```

三者都对，`*` 的空白位置不影响语义。但下面这种写法有陷阱：

```cpp
int* p_number5, other_int;   // other_int 是普通 int，不是指针！
```

`*` 只修饰紧跟其后的那个声明符。`other_int` 的类型是 `int`。课程现场打印 `sizeof` 验证了这一点：`sizeof(p_number5)` 是 8，`sizeof(other_int)` 是 4。结论是**一行只声明一个变量**，指针尤其如此。

### 取地址与解引用

```cpp
int int_var {43};
int* p_int {&int_var};          // & 取地址

std::cout << "int_var : " << int_var << std::endl;        // 43
std::cout << "p_int    : " << p_int << std::endl;          // 一个十六进制地址
std::cout << "*p_int   : " << *p_int << std::endl;         // 43
```

- `&x` 得到 `x` 的地址，类型是 `int*`。
- `*p` 沿着指针找到那个地址上的值，称为**解引用**。

指针可以被重新赋值，指向另一个同类型变量：

```cpp
int int_var1 {65};
p_int = &int_var1;      // 现在指向 int_var1
```

### 类型必须匹配

```cpp
int* p_int1 {};
double double_var {33.0};
p_int1 = &double_var;   // 编译错误
```

编译器报错类似「cannot convert `double*` to `int*`」。原因是解引用时要按类型解释内存：`int*` 会读 4 个字节并当作整数，而 `double` 是 8 字节且编码方式不同。允许跨类型赋值会让 `*p` 读出错误的结果，所以类型系统直接禁止。确实需要时要用显式转换，但那是另一回事。

## 字符指针与字符串字面量

字符指针的声明与用法与其他指针相同：

```cpp
char char_var {'A'};
char* p_char {&char_var};
std::cout << *p_char << std::endl;   // A
```

特殊之处在于可以用字符串字面量初始化：

```cpp
const char* p_message {"Hello world"};
```

编译器把字面量展开成一个字符数组（末尾带 `'\0'`），`p_message` 指向它的第一个字符。

### 为什么必须加 `const`

字符串字面量存放在只读区域，标准规定修改它是未定义行为。现代编译器要求用 `const char*` 接收：

```cpp
char* p_message {"Hello world"};        // C++11 起非法
const char* p_message {"Hello world"};  // 正确
```

课程里用 GCC 与 MSVC 各试了一次，两者都拒绝前者。这不是吹毛求疵：如果允许 `char*`，你就能写下 `p_message[0] = 'B'`，而那块内存根本不允许写。

### 打印指针与打印解引用

```cpp
const char* p_message {"Hello world"};

std::cout << p_message << std::endl;    // Hello world
std::cout << *p_message << std::endl;   // H
```

`std::cout` 对 `char*` 有特殊处理：从首地址开始逐字符输出，直到 `'\0'`，所以直接打印指针得到整串文本；而 `*p_message` 只是一个 `char`，打印出来是单个字符。这与上一章字符数组的行为完全一致——它们本来就是同一件事。

### 需要修改时用数组

```cpp
char message[] {"Hello world"};
message[0] = 'B';                 // 合法
std::cout << message << std::endl; // Bello world
```

数组有自己的可写副本；指针指向的是只读字面量。**只读文本用 `const char*`，需要修改用 `char[]`。**

### 虚拟内存

程序运行时看到的内存并不是物理 RAM，而是一张由操作系统定义的**虚拟地址空间**。64 位系统上，每个进程都以为自己拥有 $0$ 到 $2^{64}$ 的地址范围。

这样设计是为了隔离：如果每个程序都直接用物理内存，几百个程序很快就会把内存耗尽，而且一个程序可以随意读写另一个程序的数据。虚拟内存让每个进程以为自己独占全部地址空间，实际的物理页由操作系统按需分配。

### MMU 的角色

程序里的地址经过 CPU 的**内存管理单元（MMU）**翻译成真实的物理地址。整个程序不会被一次性载入内存，只有近期会用到的部分才在 RAM 中，其余留在硬盘上按需调页。这是操作系统与硬件的协作，写 C++ 时不需要手动管理，但要知道「你看到的地址不是物理地址」。

### 内存布局

一个进程的地址空间大致分为：

| 区域 | 存放内容 | 生命周期 |
| --- | --- | --- |
| text | 程序的机器码 | 整个进程 |
| data | 全局变量、静态变量 | 整个进程 |
| stack | 局部变量、函数调用信息 | 由作用域决定 |
| heap | `new` 分配的内存 | 由程序员决定 |

课程只深入 stack 与 heap，因为这两个直接决定变量的生死。

### 栈与堆的区别

```cpp
{
    int local_var {23};      // 在栈上，离开作用域即销毁
}
// local_var 已经不存在
```

栈上的变量由作用域控制生死：进入代码块时创建，离开时销毁。程序员无法让它提前结束，也无法让它活得更久。

堆则相反：

```cpp
int* p_number {new int {77}};   // 在堆上分配一个 int
std::cout << *p_number << std::endl;
delete p_number;                 // 手动归还
p_number = nullptr;              // 防止悬空
```

`new int {77}` 向操作系统申请一块足够放 `int` 的内存，写入 77，返回地址。这块内存在 `delete` 之前一直属于本程序，即使创建它的作用域早已结束。**堆把生命周期的控制权交给了程序员**，代价是必须记得归还。

### 三类必须避免的写法

```cpp
int* p_number2;      // 未初始化，里面是垃圾地址
*p_number2 = 55;     // 未定义行为，可能崩溃
```

```cpp
int* p_number3 {};   // 空指针
*p_number3 = 55;     // 未定义行为，必然无效
```

```cpp
int* p4 {new int {99}};
delete p4;
delete p4;           // 重复释放，崩溃
```

前两种课程都现场运行过：程序在写入那一行被操作系统终止，后面的 `std::cout` 根本没有执行。第三种同样会崩溃，而且更隐蔽——真实项目里两个指针可能指向同一块内存，各自 `delete` 一次就构成了重复释放。

### 使用堆内存的固定流程

1. 用指针接收 `new` 返回的地址。
2. 通过指针读写。
3. `delete` 归还内存。
4. 把指针设为 `nullptr`。

第 4 步经常被省略，但它是防止「悬空指针」的最低成本手段：之后再误用这个指针，至少是明确的空指针，而不是一块已经不属于你的内存。

> **一句话总结：** 指针存地址，类型决定怎么解释那块内存；字符指针指向只读字面量，打印它得到整串；栈由作用域管生死，堆由程序员管生死，`new` 与 `delete` 必须成对且只出现一次。

## 本章结论

- `int* p` 保存 `int` 的地址；`&x` 取地址，`*p` 解引用。
- 指针只能保存同类型对象的地址，跨类型赋值编译失败。
- 同一台机器上所有指针大小相同；`int* p, q;` 中 `q` 是普通 `int`。
- 字符指针指向字符串字面量时必须用 `const char*`；`*p` 是首字符，`p` 打印整串。
- 程序看到的是虚拟内存，MMU 负责映射到物理内存。
- 栈存放局部变量，生命周期由作用域决定；堆由 `new` / `delete` 手动管理。
- 未初始化指针、空指针解引用、重复 `delete` 都是未定义行为，通常会崩溃。

## 理解检验

**1. 指针里存的是什么？为什么 `int*` 和 `double*` 在同一台机器上大小相同？**

参考答案：指针存的是一个内存地址，即某个对象在虚拟地址空间中的位置。指针的大小由地址宽度决定，64 位系统上是 8 字节，与它指向的类型无关。类型只影响解引用时如何解释那块内存（读几个字节、按整数还是浮点编码），不改变地址本身的大小。所以在同一台机器上，`int*`、`double*`、`char*` 的 `sizeof` 都相同。

**2. `int* p; *p = 55;` 为什么危险？如果改成 `int* p {}; *p = 55;` 呢？**

参考答案：第一种情况下 `p` 未初始化，里面是随机残留的地址，可能指向其他程序或操作系统的内存；写入 55 是未定义行为，可能崩溃或破坏数据。第二种情况 `p` 是空指针，明确不指向任何有效对象，解引用同样是未定义行为，通常立即崩溃。正确做法是让指针指向一个真实对象（`int x; int* p = &x;`）或先 `new` 分配内存。

**3. `int* p_number5, other_int;` 中两个变量各是什么类型？为什么讲者建议一行只声明一个？**

参考答案：`p_number5` 是 `int*`，`other_int` 是 `int`。`*` 只属于紧跟其后的声明符，不会作用于整行。这种写法极易被误读为「两个都是指针」，课程用 `sizeof` 现场验证：前者 8 字节，后者 4 字节。因此建议一行只声明一个变量，尤其是指针。

**4. 为什么不能把 `double` 变量的地址赋给 `int*`？**

参考答案：解引用时编译器按指针的类型解释内存。`int*` 会读 4 个字节并按整数解码，而 `double` 占 8 字节、采用 IEEE 754 编码。若允许这种赋值，`*p` 读到的会是 `double` 的前半段字节，结果毫无意义，甚至可能越界。类型系统在编译期就拒绝 `double*` 到 `int*` 的隐式转换，正是为了避免这类错误。

**5. `const char* p {"Hello world"};` 中，`std::cout << p` 与 `std::cout << *p` 分别输出什么？为什么必须写 `const`？**

参考答案：`std::cout << p` 输出 `Hello world`，因为 `std::cout` 把 `char*` 当作 C 字符串，从首地址逐字符输出直到 `'\0'`；`std::cout << *p` 输出 `H`，因为 `*p` 是单个 `char`。必须写 `const` 是因为字符串字面量存放在只读区域，标准规定修改它是未定义行为；现代编译器（GCC、MSVC）都要求用 `const char*` 接收，否则直接报错。

**6. 栈和堆上的变量，生命周期分别由什么控制？使用堆内存的完整流程是什么？**

参考答案：栈上变量的生命周期由作用域控制：进入代码块时创建，离开时自动销毁，程序员无法干预。堆上内存由程序员控制：`new` 分配后一直有效，直到 `delete` 归还，与创建它的作用域无关。完整流程是：用指针接收 `new` 返回的地址 → 通过指针读写 → `delete` 归还 → 把指针设为 `nullptr`，防止后续误用形成悬空指针。

**7. 为什么重复 `delete` 同一个指针会崩溃？为什么归还后要立刻置空？**

参考答案：第一次 `delete` 已经把这块内存还给操作系统，指针仍然保存着旧地址，成为悬空指针；第二次 `delete` 会试图释放一块不再属于本程序的内存，这是未定义行为，通常导致运行时崩溃。归还后立即写 `p = nullptr`，可以让指针进入明确无效的状态：之后再误用至少能被检测为空指针，而不是悄悄读写一块已经易主的内存。
