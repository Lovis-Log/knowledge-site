## 声明、索引与边界

数组的声明要给出元素类型、名字和大小：

```cpp
int scores[10];          // 10 个 int，占 40 字节
```

这一行执行后，内存里有一段连续空间，逻辑上叫 `scores`。访问元素用下标：

```cpp
std::cout << scores[0] << std::endl;   // 第一个元素
std::cout << scores[9] << std::endl;   // 最后一个元素
```

### 下标从 0 开始

大小是 10 的数组，合法下标是 **0 到 9**，不是 1 到 10。讲者反复强调这一点，因为几乎所有初学者都会在这里数错一次。

原因是地址计算：`scores[i]` 的地址等于数组首地址加上 `i * sizeof(int)`。第一个元素与首地址的偏移是 0，所以它的下标是 0。这不是人为规定，而是连续内存布局的直接结果。

### 未初始化的元素是垃圾值

`int scores[10];` 只是分配了空间，没有写入任何值。此时读取 `scores[0]` 得到的是那块内存里原本残留的字节，可能是 0，也可能是任意数，甚至每次运行都不一样。这种值不能拿来做任何判断。

### 越界不会报错

```cpp
std::cout << scores[12] << std::endl;   // 编译通过
```

编译器不会检查下标是否在范围内。`scores[12]` 落在数组之外，读到的是别人的内存：可能是本程序的其他数据，可能是其他程序的，也可能是操作系统保留的区域。后果按严重程度排列：

- 读到垃圾值，程序继续运行但结果错误；
- 读到受保护的内存，程序立刻崩溃；
- 写入越界位置，破坏别的程序的数据，或覆盖自己的其他变量。

讲者在演示里用了一个极大的下标写入，程序当场崩溃，后续的 `std::cout` 根本没有执行。**数组边界是 C++ 交给你自己保证的责任。**

## 读写与初始化

### 用循环读写

```cpp
const size_t COUNT {10};
int scores[COUNT];

for (size_t i {0}; i < COUNT; ++i) {
    scores[i] = static_cast<int>(i) * 10;   // 写入 0, 10, 20, ...
}

for (size_t i {0}; i < COUNT; ++i) {
    std::cout << scores[i] << std::endl;
}
```

注意写入时的下标就是循环迭代器，这是 C++ 里最常见的写法之一。

### 花括号初始化

声明时直接给值：

```cpp
double salaries[5] {12.7, 7.5, 13.2, 8.1, 9.3};
```

元素个数必须与大小一致，多了会编译报错（`too many initializer values`）。

只写一部分时，**其余元素自动初始化为 0**：

```cpp
int families[5] {12, 7, 5};   // 元素为 12, 7, 5, 0, 0
```

这与「完全不初始化」完全不同：后者是垃圾值，前者是确定的 0。

省略大小时，编译器用初始值个数推导：

```cpp
int class_sizes[] {10, 12, 15, 11, 18, 17};   // 大小为 6
```

但如果既省略大小、又不给初始值，编译器无从推导，直接报错。

### `const` 数组

```cpp
const int birds[] {10, 12, 15, 11, 18, 17};
birds[2] = 8;   // 编译错误
```

`const` 加在数组上，所有元素都变成只读。适合存放不应被修改的配置表或常量序列。

### 对元素做运算

```cpp
int scores[] {2, 5, 8, 2, 5, 3, 6, 9};
int sum {0};
for (int score : scores) {
    sum += score;
}
std::cout << "Score sum : " << sum << std::endl;   // 42
```

数组本身不支持整体相加，必须逐个元素处理。

## 求长度：`std::size` 与 `sizeof`

硬编码长度是上一章就批评过的做法。C++17 提供了运行期查询：

```cpp
#include <iterator>

int scores[] {1, 2, 3, 4, 5, 6, 7, 8};
const size_t count {std::size(scores)};
for (size_t i {0}; i < count; ++i) {
    std::cout << scores[i] << std::endl;
}
```

`std::size` 返回元素个数，与数组实际长度一致；增删初始值后不需要改循环。

C++17 之前的标准做法是用 `sizeof` 相除：

```cpp
const size_t count {sizeof(scores) / sizeof(scores[0])};
```

原理是：`sizeof(scores)` 是整个数组占用的字节数，`sizeof(scores[0])` 是单个元素的字节数，相除就是元素个数。讲者现场打印过：8 个 `int` 的数组，`sizeof(scores)` 是 32，`sizeof(scores[0])` 是 4，商为 8。

这个技巧只对**真正的数组**有效。一旦数组退化为指针（例如传进函数），`sizeof` 得到的是指针大小，结果就错了——这是后面章节会 revisit 的陷阱。

### 范围 for 循环

只关心元素值、不关心下标时，范围 for 最省事：

```cpp
for (int value : scores) {
    std::cout << value << std::endl;
}
```

它自动遍历所有元素，不需要大小、迭代器和推进。代价是拿不到下标；需要下标时仍要回到传统 `for`。

## 字符数组与 C 字符串

字符数组和其他数组一样可以逐个元素声明：

```cpp
char message[5] {'H', 'e', 'l', 'l', 'o'};
for (auto c : message) {
    std::cout << c;
}
std::cout << std::endl;
```

这段代码能正常打印 `Hello`。但字符数组有一个特殊之处：可以直接整体输出。

```cpp
std::cout << message << std::endl;   // 可能打印 Hello 加上一堆乱码
```

因为 `std::cout` 遇到 `char*` 时不会按「数组」处理，而是当作**以空字符结尾的字符串**：从首地址开始逐字节输出，直到遇到 `'\0'` 为止。上面的 `message` 只有 5 个字符、没有 `'\0'`，输出就会越过数组继续读下去，直到碰巧遇到一个 0。

### 三种正确的构造方式

**方式一：手动补空字符**

```cpp
char message1[] {'H', 'e', 'l', 'l', 'o', '\0'};
```

编译器推导大小为 6。

**方式二：预留空间，让编译器补 0**

```cpp
char message2[6] {'H', 'e', 'l', 'l', 'o'};
```

大小为 6，只给了 5 个值，剩下的一个槽位被初始化为 0——恰好就是空字符。所以大小为 6。

**方式三：字符串字面量（推荐）**

```cpp
char message4[] {"Hello"};   // 大小为 6
```

双引号告诉编译器：这是一段文本，拆成字符存进去，并在末尾补 `'\0'`。这种写法可以包含空格：

```cpp
char message[] {"Hello world, how are you doing"};
```

这是课程推荐的方式，也是日常最接近「输入文本」的写法。

### 对比：什么时候会出错

```cpp
char message3[] {'H', 'e', 'l', 'l', 'o'};   // 大小 5，无 '\0'
```

`message3` 是合法的数组，但**不是合法的 C 字符串**。`std::cout << message3` 会打印 `Hello` 之后继续读越界内存，输出乱码。区别只在于最后有没有那个 `'\0'`。

课程把这三种情况放在一起对比，核心结论是：**用 `char` 数组承载文本时，必须保证末尾有空字符；用双引号字面量最省心。**

### 为什么只有字符数组能整体打印

```cpp
int numbers[] {1, 2, 3, 4, 5};
std::cout << numbers << std::endl;   // 打印一个地址，不是 1 2 3 4 5
```

`numbers` 会退化为指向首元素的指针，`std::cout` 对非字符指针打印的是地址。原因要等到第 10 章讲指针时才完全清楚；这里只需记住：**只有 `char*` 被当作字符串处理。**

> **一句话总结：** 数组是一段连续内存加一个名字，下标从 0 开始、边界要自己守；字符数组之所以能整体打印，是因为 `std::cout` 一直在找那个 `'\0'`。

## 本章结论

- `int scores[10];` 分配 10 个 `int` 的连续空间，合法下标是 0 到 9。
- 未初始化的数组元素是垃圾值；部分初始化时其余元素为 0。
- 省略大小时由初始值个数推导；既不省略也给不出初始值则报错。
- `const` 数组的元素只读。
- `std::size(arr)`（C++17）给出元素个数；旧写法是 `sizeof(arr)/sizeof(arr[0])`。
- 范围 for 适合只读元素；需要下标时用传统 `for`。
- 字符数组要能整体打印，末尾必须有 `'\0'`；推荐用字符串字面量。
- 越界读写编译通过、运行期未定义，可能崩溃或破坏其他数据。

## 理解检验

**1. 为什么大小为 10 的数组，最后一个合法下标是 9 而不是 10？**

参考答案：数组元素在内存中连续排列，`scores[i]` 的地址是首地址加 `i * sizeof(int)`。第一个元素与首地址偏移为 0，所以下标为 0；第 10 个元素的偏移是 `9 * sizeof(int)`，下标为 9。合法下标范围是 0 到 9，共 10 个。访问 `scores[10]` 已经越界，读的是数组之后的内存。

**2. `int scores[10];` 之后直接输出 `scores[0]`，会得到什么？为什么？**

参考答案：得到的是不确定的垃圾值。声明只分配内存，不写入任何值；那块内存里保留着之前使用留下的字节，所以内容取决于程序的运行环境，可能是 0，也可能是任意整数，多次运行甚至可能不同。要得到确定值，必须显式初始化（例如 `int scores[10] {};` 全部置 0）。

**3. `int families[5] {12, 7, 5};` 中下标 3 和 4 的值是什么？这与完全不初始化有什么区别？**

参考答案：下标 3 和 4 都是 0。C++ 规定：用花括号初始化时，未给出的元素执行值初始化，整型得到 0。如果写成 `int families[5];`（完全没有初始化列表），所有元素都是垃圾值，不是 0。区别在于是否出现了初始化列表：一旦出现，未列出的元素就有确定的零值。

**4. 不写数组大小、只写初始值时会发生什么？什么情况下会编译失败？**

参考答案：编译器用初始值的个数推导大小。例如 `int class_sizes[] {10, 12, 15, 11, 18, 17};` 得到大小为 6 的数组；之后再增删初始值，大小自动跟着变。如果省略大小却又不提供初始化列表，例如 `int class_sizes[];`，编译器无从推导，直接编译失败。

**5. 用 `sizeof` 求元素个数的公式是什么？为什么它对函数参数里的数组不可靠？**

参考答案：公式是 `sizeof(arr) / sizeof(arr[0])`：整个数组的字节数除以单个元素的字节数。它只对真正的数组对象有效。数组作为函数参数传递时会退化为指向首元素的指针，参数类型是 `int*`，此时 `sizeof(arr)` 得到的是指针本身的大小（本机 8 字节），而不是整个数组的大小，计算结果错误。因此函数内部应把长度作为额外参数传入，或改用自带大小的容器类型（如 `std::array`、`std::vector`）。

**6. 为什么 `char message[5] {'H','e','l','l','o'};` 用 `std::cout << message` 可能打印乱码，而 `char message[] {"Hello"};` 不会？**

参考答案：`std::cout` 对 `char*` 按 C 字符串处理：从首地址开始逐字节输出，直到遇到 `'\0'`。前者只有 5 个字符，没有空字符，输出会越过数组继续读后面的内存，直到碰巧遇到 0，于是带上乱码。后者用双引号字面量初始化，编译器会自动在末尾补 `'\0'`，数组大小为 6，输出在 `o` 之后正确停止。区别就在末尾有没有那个空字符。
