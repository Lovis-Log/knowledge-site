## 变量：一块有名字的内存

C++ 预定义了一批基本类型：`int`、`double`、`float`、`char`、`bool`、`void`，以及用于类型推导的 `auto`。它们先在内存里划出固定大小的空间，再决定这些位怎样解释。

```cpp
int age {27};
```

`age` 是那块内存**在代码里的名字**，`int` 决定它占 4 个字节、按整数解释，`27` 是写进去的位模式。变量不是抽象的"盒子"，而是实实在在的一段地址。

## bit、byte 与进制

计算机里每个 0 或 1 叫一个 **bit**；8 个 bit 组成一个 **byte**。8 位能表示 256 种组合（0–255），16 位能表示 65536 种。

### 十进制是"按权重展开"

数字 2371 可以写成：

$$
2371 = 2\times10^3 + 3\times10^2 + 7\times10^1 + 1\times10^0
$$

每一位的权重是 10 的幂。

### 二进制

二进制把权重换成 2 的幂。`10010`：

$$
1\times2^4 + 0\times2^3 + 0\times2^2 + 1\times2^1 + 0\times2^0
= 16 + 2 = 18
$$

`100101` 则是 $32+4+1=37$。三位二进制能表示 0–7，四位能表示 0–15。一般地，$n$ 位能表示

$$
0 \sim 2^n - 1 .
$$

### 十六进制：四位一组

把二进制按 4 位分组，每组恰好对应一个十六进制符号（0–9、A–F）。例如

```
1111 0000 0011 1110 0110
  F    0    3    E    6      →  0xF03E6
```

32 位写成 8 个十六进制符号，比 32 个 0/1 好读得多。位数不是 4 的倍数时，在左边补 0（padding）再分组。

### 八进制：三位一组

八进制按 3 位分组，符号是 0–7。这种做法现在很少见，课程提它是为了完整。

### 在 C++ 里写字面量

```cpp
int a = 15;        // 十进制
int b = 017;       // 八进制：前导 0，值是 15
int c = 0x0F;      // 十六进制：0x 前缀，值是 15
int d = 0b1111;    // 二进制：0b 前缀，C++14 起支持，值是 15
```

**前导 0 是个陷阱**：`017` 不是十七，而是八进制的十五。打印这四个变量，输出全是 `15`——它们在内存里是同一个数，只是写法不同。

## 整数：int

`int` 在大多数平台上占 4 个字节，用二进制存储。声明与初始化有三种写法：

```cpp
int a = 10;     // 赋值初始化
int b {10};     // 花括号初始化（braced initialization）
int c (10);     // 函数式初始化（functional initialization）
```

### 未初始化会怎样

```cpp
int elephants;   // 未初始化
```

这块内存里是**垃圾值**，读出来没有意义。花括号的空初始化 `int count {};` 则保证得到 0。

### 窄化转换：三种写法的关键差别

```cpp
int x {2.9};    // 编译错误：narrowing conversion
int y (2.9);    // 编译通过，静默截断为 2
int z = 2.9;    // 编译通过，静默截断为 2
```

C++20 里用花括号把浮点数塞进 `int` 会直接报错，这正是花括号初始化的价值：**它把"悄悄丢数据"变成了"编译不过"**。函数式与赋值式则会默默截断，2.9 变成 2，程序照样跑，结果却错了。

### sizeof

```cpp
std::cout << "sizeof(int): " << sizeof(int) << std::endl;       // 4
std::cout << "sizeof(x): "   << sizeof(x)   << std::endl;       // 4
```

既可以查类型，也可以查变量，单位是字节。`int` 在常见平台上就是 4 字节。

### 命名规则

- 首字符必须是字母或下划线，不能是数字。
- 之后可以是字母、数字、下划线。
- 区分大小写：`bikeCount` 与 `BikeCount` 是两个变量。
- 不能含空格或 `+`、`-` 这类符号。

## 整数修饰符

修饰符改变整数的符号性与宽度。**它们只能用于整数类型**，不能用于浮点数。

### signed 与 unsigned

```cpp
int a = 1;              // 默认 signed，可以存负数
signed int b = -300;    // 显式写法
unsigned int c = 4;     // 只能存非负数
unsigned int d = -5;    // 编译错误
```

两者占用的字节数相同（都是 4 字节），区别在于这 4 个字节怎样解释：有符号把最高位当符号位，无符号则全部当数值。因此范围不同：

$$
\text{unsigned}: 0 \sim 2^n-1,
\qquad
\text{signed}: -2^{n-1} \sim 2^{n-1}-1 .
$$

4 字节无符号约 0–42 亿，有符号约 −21 亿–21 亿。

### short、long、long long

| 写法 | 典型大小 | 说明 |
| --- | --- | --- |
| `short` | 2 字节 | 等价于 `short int` |
| `int` | 4 字节 | |
| `long` | 4 或 8 字节 | **依赖平台**，Windows 上通常是 4 |
| `long long` | 8 字节 | 范围极大 |

课程在 Windows + gcc 上实测：`short` 2 字节、`int` 4 字节、`long` 4 字节、`long long` 8 字节。换到 Linux，`long` 往往是 8 字节——所以**不要假设 `long` 的大小**，需要固定宽度时用 `<cstdint>` 里的 `int32_t`、`int64_t`。

`short` 能表示 −32768 到 32767，这个范围可以用上一节的公式验证：$2^{15}=32768$。

## 浮点数

浮点数表示带小数点的数。C++ 有三个类型：

| 类型 | 典型大小 | 有效数字（十进制） |
| --- | --- | --- |
| `float` | 4 字节 | 约 7 位 |
| `double` | 8 字节 | 约 15–17 位 |
| `long double` | 12 或 16 字节 | 至少与 double 相当 |

"精度"指从第一个有效数字起能可靠表示多少位。数字 `123456789012` 有 12 位，`float` 存不下，`double` 可以。

### 后缀决定字面量的类型

```cpp
float a = 1.23f;        // f 后缀
double b = 1.23;        // 默认就是 double
long double c = 1.23L;  // L 后缀
```

漏掉 `f` 是常见 bug：`float x = 1.23456789;` 里的字面量先按 `double` 解析，再转成 `float`，精度在转换时被截断。把变量类型改成 `double` 却没删 `f` 更隐蔽——变量是 `double`，存的却是 `float` 精度的值。

### 科学计数法

```cpp
double big = 1.9e8;     // 1.9 × 10^8
double small = 3.498e-11; // 3.498 × 10^-11
```

`e` 后面的数字是 10 的幂次，正数向右移小数点，负数向左移。

### 无穷大与 NaN

浮点数可以除以零，结果不是崩溃，而是特殊值：

```cpp
double a = 5.6;
double zero = 0.0;
double inf = a / zero;      // +inf
double nan = zero / zero;   // nan（not a number）
```

- 正数除以 0 得到 `inf`，负数得到 `-inf`。
- `inf + 5` 仍是 `inf`：无穷大加有限大还是无穷大。
- `0.0 / 0.0` 得到 `nan`，表示"这个运算没有有意义的数值结果"。`nan` 参与的大多数运算结果仍是 `nan`。

整数除以零是未定义行为，浮点数除以零有定义的结果——这是两类数在语义上的重要区别。

### 用 setprecision 观察精度

```cpp
#include <iomanip>

std::cout << std::setprecision(20);
std::cout << 1.234567890123456789 << std::endl;
```

默认精度是 6 位。`setprecision` 只是"要求显示多少位"，**不能突破类型本身的精度上限**：`float` 显示到第 8 位就开始出现垃圾数字，`double` 大约到第 17 位，再往后同样没有意义。

## 本章结论

- 变量是一块有名字的内存；类型决定这块内存的大小和解释方式。
- 内存里只有 0/1，二进制按 2 的幂展开，八进制三位一组，十六进制四位一组。
- C++ 字面量：`017` 是八进制，`0x0F` 是十六进制，`0b1111` 是二进制。
- 三种初始化方式中，花括号最安全：窄化会编译报错，另外两种会静默截断。
- `int` 通常 4 字节；`short` 2 字节；`long long` 8 字节；`long` 的大小依赖平台。
- `signed`/`unsigned` 改变符号性；`short`/`long` 改变宽度；修饰符只作用于整数。
- 浮点数用 `float`/`double`/`long double`，精度分别约为 7、15、更高；字面量后缀 `f`、`L` 不能漏。
- 浮点数除以零得到 `inf`，`0.0/0.0` 得到 `nan`，程序不会因此崩溃。

## 理解检验

**1. 变量 `int a = 017;` 的值是多少？如果把它打印出来，为什么和 `int b = 15;` 的输出一样？**

参考答案：`017` 是八进制字面量，值为 $1\times8+7=15$。它与 `15` 在内存里是同一个二进制数 `0000 0000 0000 0000 0000 0000 0000 1111`，只是源码里的写法不同；`std::cout` 默认按十进制输出，因此两者都打印 15。

**2. `int x {2.9};` 与 `int y (2.9);` 的行为差别是什么？为什么说前者更安全？**

参考答案：`int x {2.9};` 使用花括号初始化，从 `double` 到 `int` 属于窄化转换，C++20 会直接报 "narrowing conversion" 编译错误，程序无法生成。`int y (2.9);` 使用函数式初始化，编译器静默地把小数部分截掉，`y` 得到 2。前者把"丢数据"变成编译期可见的错误，后者把问题藏到运行时，所以前者更安全。赋值初始化 `int z = 2.9;` 与后者一样会静默截断。

**3. 为什么 `unsigned int` 和 `int` 都占 4 字节，取值范围却不同？**

参考答案：4 字节 = 32 位，两种类型能表示的状态数都是 $2^{32}$，区别在于如何解释最高位。`signed` 把最高位当符号位，剩下 31 位表示数值，范围是 $-2^{31}$ 到 $2^{31}-1$，约 −21 亿到 21 亿；`unsigned` 把 32 位全部当数值，范围是 0 到 $2^{32}-1$，约 0 到 42 亿。字节数相同，解释方式不同。

**4. 在 Windows 上 `sizeof(long)` 是 4，在 Linux 上常见是 8。这对写可移植代码意味着什么？**

参考答案：`long` 的宽度由平台的数据模型决定（Windows 用 LLP64，Linux 用 LP64），因此同一段代码在两个平台上可能表现出不同的溢出行为。写可移植代码时不要假设 `long` 的大小：需要明确宽度就用 `<cstdint>` 的 `int32_t`/`int64_t`，或者改用 `long long`（C++ 标准保证至少 64 位）。涉及序列化或二进制文件格式时尤其不能依赖 `long`。

**5. `float x = 1.234567890123;` 里漏写 `f` 会怎样？把变量类型改成 `double` 却不删 `f` 又会怎样？**

参考答案：第一种情况下，字面量按 `double` 解析（精度约 15 位），再赋给 `float`（精度约 7 位），赋值时后 8 位左右被截掉，`x` 只能保留约 7 位有效数字。第二种情况下，变量是 `double`，但字面量带 `f` 后缀，先按 `float` 存储再提升为 `double`，看起来变量更宽，实际保存的仍是 `float` 精度的值，后面的数字是没有意义的噪声。两种情况都说明：**字面量后缀与变量类型必须一致**。

**6. 整数 `7 / 0` 与浮点数 `7.0 / 0.0` 的结果有什么本质区别？**

参考答案：整数除以零在 C++ 中是未定义行为，编译器不保证任何结果，程序可能崩溃或产生任意值。浮点数遵循 IEEE 754，`7.0 / 0.0` 有明确定义的结果 `+inf`，`-7.0 / 0.0` 得到 `-inf`，`0.0 / 0.0` 得到 `nan`；程序不会因此崩溃，但后续运算可能被 `inf` 或 `nan` 污染。前者是语言层面的错误，后者是数值层面的特殊值。
