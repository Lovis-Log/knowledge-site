## 这条教程覆盖什么

目标不是做一个 landing page，而是从零交付一个**真正能收款的 SaaS**：登录、数据库、AI 功能、订阅支付、法律页面、自定义域名，全部走一遍。

示例产品是一个 AI 简历生成器，作者称其对标的同类产品月经常性收入约 25 万美元、累计收入超过 1000 万美元。教程只复刻核心功能，不追求完整产品。

> **说明：** 视频描述里包含 Cloudways、CodeRabbit 等服务的推广链接与折扣码。工具选型可以借鉴，但不必把它们当成唯一选择。

### 先看清整体循环

整条流程是一个可以反复执行的环：

1. 规划项目，把需求写成文档；
2. 依据规划生成 UI 设计；
3. 拆成功能（登录、仪表盘、数据库、支付……）；
4. 一次只做一个功能；
5. 手动自检；
6. 跑一次 AI 代码审查；
7. 修复问题，确认功能完成后进入下一个。

教程的立场很明确：**写代码正在变成便宜的环节，审查与安全保障才是稀缺的**。

## 一、准备：工具与最小概念

### 工具

| 类别 | 选择 | 说明 |
| --- | --- | --- |
| AI agent | Claude Code 或 Codex | 有哪个订阅就用哪个；都装在 VS Code 里 |
| 编辑器 | VS Code | 能看到文件结构，比纯桌面 agent 更适合初学者建立直觉 |
| 运行时 | Node.js | Next.js 的前提 |
| 版本控制 | Git + GitHub | 本地版本 + 远端备份 |
| 部署 | Cloudways Velocity（或同类） | 连接 GitHub，提交即自动部署 |
| 后端 | Neon | Postgres、认证、存储 |
| 支付 | Polar（或 Stripe、Lemon Squeezy） | 有 sandbox，测试不扣真钱 |
| 代码审查 | CodeRabbit | PR 审查 + 全库深度扫描 |

作者建议的最低成本是**一个每月 20 美元的 AI 订阅**，其余服务基本都有免费额度。

### 必须懂的六个概念

1. **前端 / 后端**：前端是你看到并操作的界面；后端是背后处理数据与逻辑的部分。两者都有就是 full-stack。
2. **数据库**：存放并组织数据的地方，有表、行、列。教程用 Postgres。
3. **认证 vs 授权**：认证回答「你是谁」（邮箱、Google 登录）；授权回答「你能做什么」（普通用户只能购买，管理员能增删商品）。
4. **Git vs GitHub**：Git 在本地记录每次改动（commit），可以回退；GitHub 把仓库放到远端，便于协作与灾难恢复。
5. **API 与 API key**：API 让两个应用互相通信（例如你的应用调用 Stripe）；API key 是调用方表明身份的密钥。
6. **环境变量与 `.env`**：API key、数据库 URL 等敏感值放在 `.env` 里，并写进 `.gitignore`，绝不提交到 GitHub。

## 二、尽早部署，而不是最后才部署

多数教程把部署放在最后，这条教程反其道而行：第一版页面一出来就先上线。

流程：

1. 在 Cloudways 创建 Velocity 服务器，选择离用户最近的区域；
2. 授权 GitHub，选择仓库；
3. 点部署。平台会自动识别 Next.js，构建并给出一个临时 URL。

之后每次向仓库推送 commit，Cloudways 会自动重新部署。教程用一个改品牌名与配色的例子演示了「本地改完 → 提交 → 线上生效」的闭环。

> **为什么值得：** 从第一天起就有一个可分享的真实 URL，后面每个功能都能立刻在线上验证，而不是等到最后才发现部署环境有问题。

平台还提供日志、部署历史与监控；出问题可以看日志、回滚到上一个可用版本。对没有专职 DevOps 的独立开发者，这部分比「部署成功」更重要。

部署失败时，把完整日志贴给 AI，并说明「我用什么部署、失败在哪里」，通常能直接得到修复建议。

## 三、规划：把 AI 的猜测空间压到最小

### 找方向

作者推荐先看已经验证过的产品（例如 trustmrr.com 上按收入排名的项目），而不是凭空想点子。选一个收入真实、功能边界清晰的产品做简化版。

### 让 AI 分析竞品并给功能清单

```text
这是一个我很喜欢的 AI 简历生成器 SaaS，我想做一个简化版。
请分析整个网站，列出它的核心功能，并给我一份可以做的 v1 功能清单。
不要包含 nice-to-have，只要核心功能。同时生成一份定价方案。
```

得到清单后，再要求「只要简化版、不要复杂」。

### 用访谈代替猜测

这是整条流程里最容易被初学者跳过、也最贵的一步。如果直接让 AI 生成计划，它会自行假设价格、试用期、目标用户等细节。

正确做法是让 AI **先面试你**：

```text
你现在的任务不是写代码或搭脚手架，而是采访我。
请分批提问，覆盖目标用户、核心流程、定价、技术约束、上线标准。
最后我描述项目时，你再整理成计划。
```

在 plan mode 下逐批回答，直到它给出完整方案。作者提醒：**要真的读问题**，不要一路点推荐选项。

### 固定技术栈

规划阶段就要把技术栈写死，否则 AI 会随机选型。示例：Next.js + Neon（Postgres、认证、存储）+ Cloudways 部署。

最后让它生成 `plan.md`，把完整计划落盘，作为后续所有会话的参考。

### 三个文件的分工

| 文件 | 读者 | 作用 |
| --- | --- | --- |
| `README.md` | 人 | 项目说明、如何启动 |
| `plan.md` | 人与 AI | 完整需求与实施计划 |
| `AGENTS.md` | AI | 每次会话自动加载的规则与约定 |

`AGENTS.md` 相当于给 agent 的项目说明书：把「始终用 Tailwind」「改动后必须提交」「交付前测试通过」这类规则写进去，就不必在每个会话重复。旧的 `CLAUDE.md` 已并入这一约定。

## 四、UI 设计：先给参考，再用假数据铺满

### 没有参考的默认结果

不给参考时，AI 生成的界面有很强的「AI 味」：用 emoji 代替图标、紫色渐变、到处是相似的卡片与动画。有经验的人一眼就能看出来。

解决办法不是换更长的提示词，而是**给参考**：去 Pinterest 搜 web design / mobile app design，挑一张喜欢的截图，直接作为图片附件交给 agent，并明确「参考它的布局、配色与氛围，不要照抄内容」。

### 生成图像与视频素材

- 图像：可以让 agent 调用 GPT Image 一类模型生成；
- 视频：教程使用 Higgsfield 的 MCP，先文生图，再图生视频，放进 hero 区域；
- 预算有限时可以用 ChatGPT / Gemini 的免费额度生成静态图，只是流程不如在编辑器里一体化。

生成后不满意就继续追加要求：去掉不工作的播放按钮、去掉滚动提示、换 logo、用同一角色生成不同场景。作者的经验是：**UI 很难一次到位，靠的是多轮参考与明确反馈**。

### 先做假数据，再做后端

一个关键策略：**先把整个前端做完，数据全部写死**。包括：

- landing page；
- 登录页；
- 仪表盘、简历列表、编辑器、账单页；
- 实时预览等交互。

这样你能在写任何后端逻辑之前，完整走一遍产品，确认信息架构与交互是否成立。之后只需让 AI「把假数据换成真实数据源」，改动范围小得多。

## 五、代码审查：把 PR 变成质量闸门

一个 UI 功能就可能改动 43 个文件，功能越加越多时会到两三百个。逐行审查不现实。

流程：

1. 从主分支切一个功能分支；
2. 提交并在 GitHub 创建 pull request；
3. 让 CodeRabbit 审查 PR；
4. 它会给出摘要、按类别整理的变更、以及每个问题的修复提示（可直接复制成 prompt）；
5. 把修复 prompt 交给 agent，修完再提交到同一分支；
6. 合并 PR，回到主分支同步。

审查覆盖的重点是安全问题：注入、授权绕过、XSS、错误的 OAuth 实现等。教程强调：这些问题 agent 会「无意识地」写出来，靠人肉几乎不可能全部发现。

> **注意：** 代码审查降低风险，但不等于安全认证。上线前仍应自己做功能与权限验证。

## 六、接入后端：数据库、登录与 AI 功能

### Neon 项目

创建项目时勾选 Postgres，以及认证、实时、存储、函数等需要的模块。Neon 会给出一个初始化提示，里面带组织 ID、项目 ID 等环境变量，把提示连同当前项目情况一起交给 agent：

```text
这个项目目前的数据全部是写死的假数据。
我想用 Neon 作为整个后端平台，请按下面的说明接好数据库与认证。
```

### 登录

在 Neon 控制台配置认证提供商（示例只用 Google），然后把控制台中看不懂的配置项截图给 agent，问「这些值需要写进代码吗？需要的话告诉我」。

作者把「截图 + 提问」当成通用技巧：任何控制台看不懂的地方都可以这样处理，包括上架 App Store 时的各种表单。

### 连接与验证

配置完成后，`.env` 会自动出现数据库 URL、认证 URL、JWK 等值；这些文件已被 `.gitignore` 忽略。注册、登录后在 Neon 的认证用户表里应能看到新用户。

随后把简历的增删改查从假数据切到数据库，验证创建、编辑、下载 PDF 等主流程。

### AI 功能

1. 在 OpenAI（或 Gemini、Anthropic）创建 API key；
2. 写进 `.env.local`；
3. 让 agent 用这个 key 实现生成功能；
4. 用真实数据测试，确认积分扣减、接受/拒绝建议等行为。

### 上线前的环境变量

把 `.env` 里的键值逐条加到 Cloudways 的环境变量面板，标记为 sensitive，然后**重新部署**——新增环境变量不会自动生效。

还要把生产域名加入 Neon 的认证允许列表，否则线上登录会失败。

## 七、收款：Polar 的 sandbox 与 webhook

### 商品与凭据

在 Polar 的 sandbox 环境创建产品：订阅制、每月 9 美元、固定价格。然后准备三个值：

| 值 | 用途 |
| --- | --- |
| Product ID | 标识要购买的商品 |
| Access Token | 服务端调用 Polar API |
| Webhook Secret | 验证回调确实来自 Polar |

### webhook 是什么

支付成功后，Polar 会向你的后端发送一条自动消息：「这个用户已付款」。你收到后为其开通权限。

关键在验证来源：如果不校验签名，任何人都可以伪造「我已付款」的请求。Webhook Secret 就是用来确认消息确实来自 Polar 的。教程用一个本地转发的命令行工具把 webhook 转到 localhost，并保持该终端运行以便测试。

### 测试

sandbox 使用测试卡：卡号填一串 42，有效期填未来日期，CVC 任意。付款成功后应跳转成功页并开通 Pro。教程中首次跳转后出现错误，把报错截图交给 agent 后修复。

上线时把 sandbox 的三个值换成正式环境的对应值，写进 Cloudways 环境变量并重新部署。

## 八、深度扫描与法律页面

### AI Deep Scan

PR 审查只看本次改动；深度扫描会检查**整个代码库**，包括多年未动的旧代码，并可按计划运行（例如每周一）。计费按使用量。

教程用另一个仓库做了验证：故意植入多类漏洞，再跑深度扫描，结果检出 8 个 critical/high、2 个 medium、1 个 low。报告里的问题可以直接生成修复请求、派发工单或忽略，也可以分享给 agent 或队友。

常见类别：IDOR、授权绕过、XSS、OAuth 配置错误、注入。

### 法律页面

用作者提供的 prompt 生成服务条款与隐私政策，放在 `/terms` 与 `/privacy`。它会先读代码库，再按实际收集的数据写内容。

**生成后必须替换占位符**：法律实体名称、地址、联系方式等，AI 无法猜对。建议把所有真实值一次性交给 agent，让它统一替换。

## 九、自定义域名

1. 在 Cloudflare 购买域名（作者称价格通常更低）；
2. 在 Cloudways 的域名管理里添加域名（根域 + `www`）；
3. 按提示拿到 CNAME 记录的名称与目标；
4. 回到 Cloudflare 的 DNS，添加两条 CNAME：`@` 与 `www`，目标填 Cloudways 给出的值，代理状态设为 **DNS only**；
5. 等待生效（几分钟到 24 小时）。

域名生效后若应用报错，先检查生产环境变量是否齐全、是否重新部署；再检查 Neon 是否已加入新域名。

## 可复现检查清单

- [ ] 第一天就有一个可访问的线上 URL，并验证「提交即部署」；
- [ ] `plan.md` 通过访谈生成，价格、用户、范围都已明确；
- [ ] `AGENTS.md` 写入了提交与测试规则；
- [ ] UI 有明确的参考图，且用假数据跑通全部页面；
- [ ] 每个功能都经过「分支 → PR → AI 审查 → 修复 → 合并」；
- [ ] 数据库、认证、AI key 均通过环境变量注入，`.env` 未入库；
- [ ] 支付在 sandbox 用测试卡跑通，webhook 验签生效；
- [ ] 上线前跑过一次全库深度扫描；
- [ ] 法律页面的占位符已替换；
- [ ] 自定义域名、生产环境变量、认证回调域名三者一致。

## 边界与提醒

- **这是特定工具链的演示**：Cloudways、Neon、Polar、CodeRabbit 都可以替换，步骤会变，但「先部署、先规划、假数据先行、审查兜底」的原则不变。
- **AI 生成不等于可维护**：教程用 UI 套假数据的方式快速成型，后期仍需要真实数据迁移与边界处理。
- **安全不是一次扫描**：深度扫描能发现已知模式的问题，权限设计与业务逻辑漏洞仍需人来判断。
- **成本**：AI 订阅、服务器、域名、支付手续费、审查服务都要计入；教程多次使用赞助与免费额度，实际长期成本需自行核算。
