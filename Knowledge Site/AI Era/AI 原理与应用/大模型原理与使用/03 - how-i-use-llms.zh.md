## 从「一个文本框」到一整套工具

上一篇讲的是模型怎么被训练出来；这一篇讲实际怎么用。Karpathy 的出发点很朴素：ChatGPT 是 2022 年第一个让人们能直接和模型对话的产品，但到 2025 年，生态已经变成一堆互相竞争的聊天应用，每个都在加自己的工具。

他的使用原则可以先用一句话概括：**先判断这个任务需要模型的哪种能力，再决定用哪个模型、开哪个工具、要不要给材料**。剩下的内容都是这句话的展开。

## 先理解你在操作什么

### 聊天气泡背后是一条 Token 流

界面上是你一句、模型一句。底层只有一条一维 Token 序列：你写一段，模型接着往下写一段，写完发一个「我说完了」的特殊 Token，控制权交回给你。

点「新对话」，就是把这条 Token 序列清空，从头开始。

这条序列就是**上下文窗口**，也就是模型的**工作记忆**：窗口里的内容，模型每一步都能直接读到；窗口外的内容，模型一无所知。

### 模型是一个压缩包

Karpathy 给了一个有点粗糙但很好用的比喻：模型像一个几 TB 的压缩包。

- 预训练把互联网压进参数，这是**有损压缩**，留下的是统计规律与模糊记忆，不是原文数据库；
- 后训练给它加上「助手人格」，相当于给压缩包贴了一张笑脸；
- 压缩包本身不会上网、不会算数、不会运行代码——除非你给它接工具。

这个比喻直接推出两条使用原则：

1. 知识有截止日期，越近期、越冷门的信息越不可靠；
2. 默认状态下它没有工具，所有「查一下」「算一下」都只能靠记忆猜。

## 基础用法与两个习惯

### 什么时候可以放心问

咖啡因含量、常见药物成分、旅游建议这类问题，Karpathy 会直接问，理由是：

- 不涉及近期变化；
- 互联网上讨论极多，模型记忆充分；
- 不是高风险决策，答案错了代价可控。

即便如此，他仍会核对原始来源。对药物成分，他直接拿起药盒对照——因为模型给的是概率性回忆，不是事实查询。

### 习惯一：换话题就开新对话

上下文窗口有两种成本：

- **注意力成本**：历史越长，无关内容越会分散模型注意力，降低回答质量；
- **计算成本**：Token 越多，每生成一个词就越慢、越贵。

所以换话题时开新对话，是最便宜的质量优化。

### 习惯二：知道自己用的是哪个模型

同一家公司往往有多个档位：免费版可能是小模型，付费版才是旗舰。Karpathy 的做法是明确记住自己当前在用哪个模型，并根据任务决定值不值得升级。

他的个人取舍是：日常大部分问题用旗舰非推理模型；遇到难题再切推理模型；专业工作中同时订阅多家，形成自己的「LLM 议会」——同一个问题问几家，比较答案。

## 什么时候需要推理模型

推理模型是在强化学习阶段额外训练过的模型：它会花更多 Token 在内部试错、回退、重算。代价是慢，收益是难题上的准确率。

一个真实例子：Karpathy 的梯度检查失败，他把代码贴给 GPT-4o，模型列出一堆「可能的原因」，但没有指出真正的问题。换成推理模型后，它思考了一分钟，发现是参数打包与解包时顺序不匹配。

但要注意两点：

- 简单问题用推理模型是浪费，查资料、闲聊不需要等一分钟；
- 推理能力不是推理模型独有。同一个 bug，Claude 3.5 Sonnet（当时并非推理模型）也直接找到了。

实践策略：先用快速模型；如果回答明显不够好，再切到推理模型重问。

## 工具：让模型「看到」而不是「回忆」

### 联网搜索

模型的知识截止在训练时，近期信息它不可能知道。搜索工具的做法是：模型发出一个搜索请求的特殊 Token，应用程序暂停生成，去搜索引擎取回网页文本，把文本塞进上下文窗口，然后模型基于这些文本回答，并附上引用。

适合搜索的问题有明显特征：

- 有时效性（今天的行情、这周的上映时间）；
- 冷门（某部剧在哪里拍的）；
- 会变化（某公司是否提供某服务）。

**引用必须点开核对**。搜索降低了幻觉，但没有消除：它可能误读网页，也可能引用不支持结论的来源。

不同产品的搜索集成程度不同。有的模型会自动判断需要搜索，有的必须手动开启，有的根本没有这个工具——同一个问题在不同应用里的结果可能完全不同。

### 深度研究

深度研究是「搜索 + 推理 + 长时间运行」的组合：模型会发起几十次搜索、读大量论文与网页，几十分钟后交出一份带引用的报告。

它适合：

- 需要多来源整合的主题（某补剂的机制、安全性与人体试验证据）；
- 产品对比（两个浏览器的隐私策略）。

它不适合：

- 需要精确数字的表格。Karpathy 让它整理「美国主要 LLM 实验室」的规模与融资表，结果漏掉了 xAI，还把非美国机构算了进来。

结论：把它当**高质量初稿 + 文献入口**，不要当事实数据库。

## 把材料放进上下文

### 上传文件

比起让模型「记得」某篇论文，直接把 PDF 拖进对话更可靠。文件会被转成文本、载入上下文，然后可以逐段提问。

一个实际做法是「一起读书」：找到《国富论》某一章的原文，粘贴进对话，先让模型总结，再边读边问。Karpathy 说这显著提高了他的理解与记忆，尤其是跨领域或年代久远的文本。

注意底层细节：大 PDF 里的图片很可能被丢弃，只保留文字；扫描件效果取决于 OCR。

### Python 解释器

心算不可靠，代码可靠。ChatGPT 会在遇到复杂计算时自动写 Python、执行、把结果读回来。

对比实验很说明问题：

- ChatGPT 调用了解释器，结果正确；
- Grok 3（当时没有解释器）硬算，答案非常接近但错了；
- Claude 写 JavaScript 算，正确；
- Gemini 心算，简单题对、加大数字后错。

**同一个问题，工具决定了对错**。所以遇到数字、日期、字符串处理，主动要求「用代码算」。

### 高级数据分析

上传表格后，模型可以写代码做统计与作图。它确实能很快产出图表，但也会悄悄做假设。

Karpathy 的例子：让模型画 OpenAI 估值曲线，2015 年数据是 N/A，模型在代码里直接写成 0.1（即 1 亿美元），没有告诉他；后来拟合外推 2030 年估值，口头说 1.7 万亿，代码里打印的却是另一个数量级。

教训是：**把它当粗心的初级分析师**。看它写的代码，核对它做的假设，不要只看结论。

### Artifacts 与概念图

Claude 的 Artifacts 会把生成的 React 代码直接在浏览器里渲染成一个小应用，比如用它生成的单词卡应用。对个人使用很方便，但没有后端与数据库。

Karpathy 最常用的是**概念图**：让 Claude 把一章内容画成 Mermaid 图，把论证结构空间化。对视觉型学习者，这比线性摘要更容易记住。

### 在代码库里工作

专业写代码时，网页聊天不够用：它看不到你的文件。Cursor 这类工具直接读取项目文件，把相关上下文自动组织好，再调用模型。

演进路径很清晰：`Cmd-K` 改一行 → `Cmd-L` 解释一段 → `Cmd-I`（Composer）让 Agent 跨文件改代码、执行命令。最后这种「把控制权交给 Agent、看它能不能跑通」的方式，就是所谓 vibe coding。

风险同样明显：它可能引入不存在的依赖、下载来路不明的资源。Karpathy 的态度是：**最终仍然可以回到普通编程**，文件都在，随时可以自己改。

## 多模态：语音、图像、视频

### 语音输入输出

最简单的形态是「语音转文字」：麦克风把话转成文本，再走普通对话流程；输出侧用「朗读」把文字转成语音。桌面端没有内置麦克风时，可以用系统级的转写工具。

它的本质仍是文本，只是把输入输出变快了。Karpathy 说大约一半的查询是语音，因为打字太慢。

### 高级语音

高级语音是「真音频」：模型直接把音频切成片段、量化成 Token，与文本同一套机制处理。它可以直接听、直接说，中间没有文本。

演示里能听出区别：可以让它换声音、讲故事、数数、模仿动物；它也会因为安全策略拒绝某些请求。

不同产品的风格差异很大，有的克制，有的几乎不设限。

### NotebookLM 与播客

把资料作为「来源」上传后，NotebookLM 可以生成一段播客式对话，还能在中途插话提问。适合通勤、散步时了解一个自己只有泛兴趣的冷门主题。

### 图像输入

图像会被切成小块、量化成 Token，和文本进入同一个模型。实际使用时，Karpathy 有一个很值得抄的习惯：**先让模型把图里的关键信息转写成表格**，确认它看对了数字，再基于文本提问。

他做过的事包括：读营养成分表、读体检报告截图、读牙膏成分、解释一个梗图。对医疗类信息，他的判断是：常见检查指标模型大概率见过足够多资料，但仍应与医生核对。

### 图像与视频生成

图像生成在 ChatGPT 里不是同一个模型：语言模型先写出描述，再交给专门的图像模型。视频生成同理，Sora、Veo 等工具负责这一环。

视频输入则是摄像头实时对话：把镜头对准书本、仪器、地图，模型能识别并解释。底层很可能仍是按帧取图，但用户体验上像在「看视频」。

## 让它更懂你：记忆与自定义

### 记忆

默认每次新对话都从零开始。ChatGPT 的记忆功能会把「关于你的几条事实」存进一个独立数据库，并在每次对话开头自动附加。

Karpathy 的体验是：用久了确实更贴合个人偏好，但记忆需要显式触发，也可以手动增删。其他产品当时还没有同等功能。

### 自定义指令

把「希望它怎么说话」写成全局设置：语气、是否展开解释、语言学习时的敬语级别等。这样不必每次重复交代。

### Custom GPT

本质是**把一段常用提示词固化下来**。Karpathy 用它做韩语学习工具：

- 词汇提取器：给一句话，输出「韩语;英语」格式，可直接导入 Anki；
- 详细翻译器：先给整句翻译，再逐词拆解，并允许追问；
- 截图翻译器：先 OCR，再翻译，再拆解。

关键在于提示词里给了**具体示例**（few-shot），而不只是描述任务。这和训练模型时的「用示例编程」是同一个道理：描述决定方向，示例决定精度。

## 本节结论

- 上下文窗口是模型的工作记忆；换话题就开新对话，既省注意力也省钱。
- 先确认自己在用哪个模型与档位，再决定是否升级。
- 推理模型适合难题，不适合日常；先用快的，不够好再换。
- 搜索、深度研究、文件上传、代码执行，本质都是**把可靠信息放进上下文**，替代不可靠的记忆。
- 引用要核对；数据要验算；代码要读。工具降低幻觉，但不消除幻觉。
- 多模态只是把音频、图像也变成 Token，机制不变。
- 记忆、自定义指令、Custom GPT 都是在减少重复交代，把稳定的偏好前置。

## 理解检验

**1. 为什么「换话题就开新对话」既提升质量又降低成本？**

参考答案：质量方面，注意力权重在每个请求的所有可见 Token 上归一化，历史里与新任务无关的内容会分走权重，稀释关键指令，模型更容易跑题或抓错重点。成本方面，上下文越长，每生成一个 Token 需要读取和计算的内容越多，延迟与费用都上升；若开启了提示词缓存，前缀变化还会导致缓存失效。开新对话会把窗口清空，让注意力集中在当前任务，同时减少每次请求携带的 Token。

**2. 联网搜索为什么能减少幻觉？它为什么不能消除幻觉？**

参考答案：搜索把网页正文放进上下文窗口，模型回答时可以引用眼前的文本，而不是依赖参数里的模糊记忆；这解决了「知识截止」和「冷门事实记不清」两类问题，并附带可核对的来源。但它不能消除幻觉，因为：模型可能误读网页内容；可能引用并不支持结论的来源；也可能在整合多段文本时做出错误推断。搜索改变的是信息来源，不改变模型「生成最可能的下一个 Token」这一本质。

**3. 在 Karpathy 的乘法对比实验中，为什么不同模型的结果差异那么大？这对日常使用有什么启示？**

参考答案：差异主要来自是否真的调用了代码执行工具。调用解释器的模型把计算交给 Python，得到精确结果；没有该工具、或选择心算的模型只能在一个 Token 里完成大数乘法，容易出错，而且错误很接近正确答案，具有迷惑性。启示是：遇到数字计算、字符串处理、日期换算这类「一步到位但计算量大」的任务，应主动要求模型使用代码工具，而不是接受它给出的心算结果；同时要清楚不同应用提供的工具并不相同。

**4. 深度研究适合什么任务？为什么它产出的表格不能直接采信？**

参考答案：它适合需要多来源整合、需要读大量文献或网页、且结论允许一定模糊性的任务，例如研究某个补剂的机制与安全性、比较两个产品的隐私策略。它不适合需要精确、完整、可核对的数字表格。因为报告由模型在长时间运行中整合生成，仍可能遗漏关键对象（如漏掉某家实验室）、把非目标对象算进来、或给出未经核实的数字。正确用法是把它当作高质量初稿与文献入口，再回到原始来源逐条核对。

**5. 高级数据分析的例子说明了什么风险？使用这类工具时应该检查什么？**

参考答案：例子中模型在代码里把缺失值 N/A 擅自替换成 0.1（1 亿美元），又在报告里把 2030 年外推值说成 1.7 万亿，而代码实际打印的是另一个数量级。风险在于：模型会**静默地做假设**，并可能在文字结论与代码结果之间出现不一致。使用时应检查三件事：它如何处理缺失值与异常值；代码里的关键常数与单位是否正确；口头结论是否与代码输出一致。把模型当粗心的初级分析师，而不是可信的分析师。

**6. 为什么 Custom GPT/自定义指令能提高效果？它的本质是什么？**

参考答案：本质是把一段稳定的提示词（含角色、任务描述与若干示例）固化下来，避免每次重复输入，并保证每次任务使用同一套约束。效果提升主要来自两点：一是提示词里包含具体示例（few-shot），示例比纯描述更能约束输出格式与判断标准；二是全局指令把长期偏好前置，减少每轮对话中的重复与遗漏。它没有改变模型能力，只是把「提示工程」变成了可复用、可管理的配置。
